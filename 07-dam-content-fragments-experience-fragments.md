## Digital Asset Management (DAM)

### DAM Structure in JCR
```
/content/dam/
├── mysite/
│   ├── images/
│   │   └── hero.jpg               [dam:Asset]
│   │       └── jcr:content        [dam:AssetContent]
│   │           ├── metadata       [nt:unstructured] → EXIF, title, tags
│   │           └── renditions/    [nt:folder]
│   │               ├── original   → Original uploaded file
│   │               ├── cq5dam.thumbnail.140.100.png
│   │               ├── cq5dam.thumbnail.319.319.png
│   │               └── cq5dam.web.1280.1280.jpeg
│   └── videos/
│       └── promo.mp4
```

### DAM Processing Workflow

When an asset is uploaded:
1. **DAM Update Asset** workflow triggers
2. Creates renditions (thumbnails, web-optimized)
3. Extracts metadata (EXIF, XMP, IPTC)
4. Generates full-text index
5. Runs custom processing steps (if configured)

### Asset Renditions
- **Original** — Uploaded file (never modified)
- **Web renditions** — Resized for web delivery
- **Thumbnails** — Small previews for DAM UI
- **Custom** — Generated by workflow or processing profiles

### Processing Profiles
Define automated transformations for uploaded assets:
- Image profiles (resize, crop, format convert)
- Video profiles (transcode to different formats)
- Metadata profiles (auto-apply metadata schemas)

### Dynamic Media (Licensed Feature)
- Serves assets with URL-based transformations
- Image Smart Crop (AI-based)
- Responsive images (serve optimal size per device)
- Example: `/content/dam/hero.jpg/_jcr_content/renditions/original?width=800&quality=80`

## Content Fragments

Structured, channel-agnostic content that can be used across pages, apps, and headless delivery.

### Content Fragment vs Component
| Aspect | Content Fragment | Component |
|--------|-----------------|-----------|
| Storage | `/content/dam/` | On the page node |
| Reuse | Multi-channel (web, mobile, API) | Page-specific |
| Authoring | Dedicated CF editor | Component dialog |
| API delivery | JSON via CF API | HTML rendering |
| Structure | Content Fragment Model | Component dialog |

### Content Fragment Model
Defines the schema (like a database table definition):
- Location: `/conf/mysite/settings/dam/cfm/models/`
- Field types: Single-line text, Multi-line text, Number, Boolean, Date, Enumeration, Content Reference, Fragment Reference, JSON Object

### Content Fragment Model Example
```
Article Model:
├── headline (Single-line text, required)
├── author (Single-line text)
├── publishDate (Date & Time)
├── body (Multi-line text, Rich Text)
├── category (Enumeration: News, Blog, Case Study)
├── relatedArticles (Fragment Reference, multiple)
├── heroImage (Content Reference → DAM)
└── tags (Multi-line text, multiple values)
```

### Accessing Content Fragments

**In HTL:**
```html
<sly data-sly-use.cfModel="com.myapp.core.models.ArticleModel">
    <article>
        <h1>${cfModel.headline}</h1>
        <p class="meta">By ${cfModel.author} | ${cfModel.publishDate}</p>
        <div>${cfModel.body @ context='html'}</div>
    </article>
</sly>
```

**Via Content Fragment API (Java):**
```java
Resource cfResource = resolver.getResource("/content/dam/mysite/articles/my-article");
ContentFragment fragment = cfResource.adaptTo(ContentFragment.class);

String headline = fragment.getElement("headline").getContent();
String body = fragment.getElement("body").getContent();
```

**Headless JSON Delivery:**
```
GET /content/dam/mysite/articles/my-article.model.json
```

### Content Fragment Variations
- **Master** — Default/primary content
- **Variations** — Alternative versions (e.g., "Short", "Email", "Social")
- Each variation can override any field from Master

## Experience Fragments

Reusable groups of components (content + layout) for cross-channel use.

### Content Fragment vs Experience Fragment
| Aspect | Content Fragment | Experience Fragment |
|--------|-----------------|-------------------|
| Content | Structured data (text, numbers) | Components + layout |
| Layout | No (content only) | Yes (HTML structure) |
| Delivery | JSON/headless | HTML snippet |
| Use case | Headless, multi-channel text | Headers, footers, promos, offers |
| Variations | Data variations | Visual variations (Web, Email, Social) |
| Location | `/content/dam/` | `/content/experience-fragments/` |

### Experience Fragment Variations
- **Web** — For website (responsive HTML)
- **Plain HTML** — Minimal HTML export
- **Email** — Inline CSS, email-compatible
- **Social** — Open Graph / social card format

### Experience Fragment Structure
```
/content/experience-fragments/mysite/en/header/
├── jcr:content
│    ├── sling:resourceType = "cq/experience-fragments/components/experiencefragment"
│    └── cq:xfVariantType = "web"
├── master/           → Default variation
│    └── jcr:content/
│         └── root/
│              ├── navigation [myapp/components/navigation]
│              └── logo       [myapp/components/logo]
└── email/            → Email variation
     └── jcr:content/
```

### Using Experience Fragments in Pages
```html
<!-- Experience Fragment component in HTL -->
<sly data-sly-resource="${'experiencefragment' 
    @ resourceType='cq/experience-fragments/components/experiencefragment',
    decorationTagName='div'}"/>
```

## Content Services (Headless AEM)

### JSON Exporter
AEM can deliver content as JSON for headless consumption:

```
# Page as JSON (Sling Model Exporter)
/content/mysite/en/home.model.json

# Content Fragment JSON
/content/dam/mysite/articles/my-article.model.json

# Custom depth
/content/mysite/en/home.model.json?depth=2
```

### GraphQL API (AEM 6.5.10+ / AEMaaCS)
```graphql
{
  articleList(
    filter: { category: { _expressions: [{ value: "News" }] } }
    _sort: "publishDate"
  ) {
    items {
      headline
      author
      publishDate
      body { html }
      heroImage { ... on ImageRef { _path width height } }
    }
  }
}
```

**GraphQL Endpoint:**
```
POST /content/cq:graphql/mysite/endpoint.json
```

## MCQs — DAM, CF & XF

### Q1: Where are Content Fragments stored in AEM?
- A) /content/fragments
- B) /content/dam ✅ **CORRECT**
- C) /apps/fragments
- D) /conf/fragments

> **Explanation:** Content Fragments are stored as DAM assets under `/content/dam/`.

### Q2: What defines the schema/structure of a Content Fragment?
- A) Content Fragment Template
- B) Content Fragment Model ✅ **CORRECT**
- C) Component Dialog
- D) Sling Model

> **Explanation:** Content Fragment Models (in `/conf`) define the fields and their types.

### Q3: Which is used for reusable layout + components (like a shared header)?
- A) Content Fragment
- B) Experience Fragment ✅ **CORRECT**
- C) Static Template
- D) Sling Model

> **Explanation:** Experience Fragments contain components with layout — perfect for shared page sections.

### Q4: What triggers DAM asset processing when a file is uploaded?
- A) A cron job
- B) DAM Update Asset workflow ✅ **CORRECT**
- C) Manual trigger only
- D) OSGi event listener

> **Explanation:** The "DAM Update Asset" workflow is launched automatically on asset upload.

### Q5: How do you deliver Content Fragment data as JSON?
- A) Custom servlet only
- B) Using .model.json extension or GraphQL ✅ **CORRECT**
- C) JSP rendering
- D) Export to file system

> **Explanation:** AEM provides JSON export via Sling Model Exporter (`.model.json`) and GraphQL API.

### Q6: What is a Content Fragment Variation?
- A) A different file format
- B) An alternative version of the same content ✅ **CORRECT**
- C) A different language translation
- D) A workflow state

> **Explanation:** Variations let you have alternate versions (e.g., short/long/social) of the same fragment.

### Q7: What rendition type contains the originally uploaded file?
- A) cq5dam.web.1280.1280
- B) original ✅ **CORRECT**
- C) cq5dam.thumbnail
- D) master

> **Explanation:** The `original` rendition is the untouched uploaded file.

### Q8: Which XF variation type uses inline CSS for compatibility?
- A) Web
- B) Plain HTML
- C) Email ✅ **CORRECT**
- D) Social

> **Explanation:** Email variation generates HTML with inline CSS since email clients don't support external stylesheets.
