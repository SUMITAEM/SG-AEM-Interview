Section 01What is CCAR-F?

The Claude Certified Architect Foundations (CCAR-F) is the highest-level foundational certification in Anthropic's Claude certification program. It validates your ability to design, build, and orchestrate production-grade AI systems using Claude.

CCAR-F in One Sentence

Proves you can architect multi-agent systems, design tool ecosystems, manage context windows, implement guardrails, and make cost/latency trade-offs for Claude-based production applications.

Who Should Take CCAR-F?

  • AI/ML Architects designing enterprise Claude integrations
  • Senior Developers building multi-agent systems
  • Technical Leads making model selection and architecture decisions
  • Platform Engineers setting up Claude infrastructure
  • Solutions Architects advising clients on Claude adoption

Prerequisites

No formal prerequisites You can take CCAR-F without first passing CCAO-F or CCDV-F. However, Anthropic recommends having developer-level Claude experience. You should be comfortable with the Messages API, tool use, prompt engineering, and have built at least one agent with Claude.

Section 02Complete Exam Syllabus — 18 Topics

The CCAR-F exam covers 4 domains with 18 topics total. Each domain tests a different architectural competency.

Domain 1: Agentic Architecture & Orchestration

How to design, implement, and manage autonomous agent systems.

Topic 1 — The Agentic Loop
Understanding and implementing the core agent execution cycle
  • What is the agentic loop (request → reason → tool_use → execute → result → reason → response)
  • Understanding the stop_reason field (end_turn, tool_use, max_tokens, refusal)
  • How to branch on tool_use and append tool results to history
  • How to continue the loop correctly with termination conditions
  • Common mistake: Skipping history on tool results
  • Common mistake: Ending the loop too early
Topic 2 — Hub-and-Spoke Model
Multi-agent orchestration with coordinator and worker agents
  • How communication flows in hub-and-spoke (one-way delegation)
  • How a coordinator decomposes tasks, invokes subagents, and passes context
  • How to aggregate results and handle subagent errors
  • Why subagents have no memory of the coordinator
  • How to diagnose incomplete coordinator output
  • Multi-agent workflow patterns (sequential, parallel, router)
  • Retrieval-Augmented Generation (RAG) with Claude
Topic 3 — Task Tool and Parallel Execution
Spawning and managing concurrent agent tasks
  • Why coordinators need task in allowedTools
  • How to run subagents in parallel vs sequential
  • What is the stakes-proportionate rule (match review depth to risk)
Topic 4 — Programmatic Control and Hooks
Code-level enforcement beyond prompts
  • What is a programmatic gate (code-level check, not a prompt)
  • PreToolUse hooks (block/modify before execution)
  • PostToolUse hooks (format/test/log after execution)
  • Why prompts alone cannot guarantee correctness

Domain 2: Tool Design & MCP Integration

How to design, describe, and manage tools for Claude agents.

Topic 5 — Tool Descriptions
Writing descriptions that drive correct tool selection
  • Why tool descriptions drive selection (poor description = wrong tool)
  • What vague descriptions look like and how to diagnose misselection
  • How to write a complete description (what + when + returns + vs similar)
  • Why the "vs similar tools" clause matters most
  • Claude Vision and multimodal inputs
Topic 6 — Error Handling Patterns
Designing robust error responses for agents
  • How to handle transient, validation, business logic, and permission failures
  • Access failure vs valid empty result (critical distinction)
  • How to design distinguishable error responses
Topic 7 — MCP Configuration
Connecting Claude to external tools via Model Context Protocol
  • What goes in project-level vs user-level MCP config
  • How to diagnose missing MCP server access
Topic 8 — Tool Scoping and Agent Roles
Principle of least privilege for agent tool access
  • Why too many tools hurt selection (token cost, ambiguity)
  • How many tools each agent should have (5-15 rule)
  • How to scope tools to agent roles (researcher, coder, reviewer, deployer)

Domain 3: Claude Code Configuration & Workflows

How to configure Claude Code for teams and production workflows.

Topic 9 — CLAUDE.md Hierarchy
Layered instruction system for projects
  • The 4-level hierarchy: user → project → directory → subdirectory
  • What goes in each level (preferences vs standards vs module rules)
  • How to diagnose ignored team conventions
Topic 10 — Agent Skills
Packaged, repeatable workflows
  • CLAUDE.md vs skills: how loading differs (auto vs on-demand)
  • Where universal standards vs task-specific workflows belong
  • Skills compared to everything else (CLAUDE.md vs Skills vs Hooks vs MCP)
  • Advanced skills: configuration and scaling
Topic 11 — Path-Specific Rules and Context: Fork
Context isolation for monorepo patterns
  • What is context:Fork and when to use it
  • Path-specific rules vs directory CLAUDE.md
  • How path-specific rules affect the token budget
Topic 12 — CLI Flags and CI/CD
Automating Claude Code in pipelines
  • What the -p flag does (headless/pipe mode)
  • How to run Claude Code in CI/CD (GitHub Actions, GitLab)

Domain 4: Prompt Engineering & Structured Output

Advanced prompting, schema design, and production optimization.

Topic 13 — Match Criteria and Few-Shot Examples
Precise control over Claude's decision-making
  • Why "only if you're confident" doesn't work (anti-pattern)
  • How to write explicit match criteria with objective conditions
  • How to define non-matches and edge cases
  • When and how many few-shot examples to use (3-5)
  • Showing reasoning in examples, not just answers
Topic 14 — JSON Schema and Structured Output
Guaranteed schema conformance for production
  • Preventing syntax errors with JSON schema (output_config.format)
  • Handling fabricated data and empty fields (nullable types)
  • Using optional, nullable fields, and enum values
  • Retry-with-error-feedback technique for business validation
Topic 15 — API Selection and Cost vs Latency
Making informed model and API choices
  • When to use synchronous vs batch API
  • Choosing between cost and latency (model routing strategies)
  • Prompt caching and extended thinking trade-offs
Topic 16 — Context Window Management
Preventing context rot and managing long conversations
  • Progressive summarization and detail loss
  • Case-facts blocks for preserving critical information
  • The "Lost in the Middle" problem and mitigation
  • Placing key findings at the top of tool results
  • Using structured tags and trimming verbose results
Topic 17 — Escalation Triggers
When to stop automation and involve humans
  • Valid triggers: human requests, authority gaps, verification flags
  • Why frustration or complexity alone are NOT valid triggers
  • Handling frustrated customers with simple issues
  • When to escalate immediately (safety, legal, financial)
Topic 18 — Error Context and Common Mistakes
Avoiding the top pitfalls in agentic systems
  • Structured error context in multi-agent systems
  • Importance of suggesting alternative approaches in error responses
  • Common mistake: waiting until retries are exhausted for non-retryable errors

Take the 87-question practice test. Review weak areas. Re-read official docs for topics you scored low on. Schedule and take the exam.

Section 09Exam Day Checklist

Before the Exam

  • Confirm exam date, time, and timezone
  • Test your internet connection (wired preferred over WiFi)
  • Test webcam and microphone
  • Have a valid government-issued photo ID ready (passport, driver's license)
  • Prepare a clean, quiet room with good lighting
  • Close all other browser tabs and applications
  • Clear your desk — no notes, no phone, no second monitor
  • Install any required proctoring software in advance
  • Disable browser notifications and system notifications
  • Have a glass of water nearby (usually allowed)
  • Use the restroom before starting

During the Exam

  • Read each question carefully — look for keywords like "NOT," "BEST," "FIRST," "MOST LIKELY"
  • Eliminate obviously wrong answers first, then choose from remaining options
  • Don't spend more than 2 minutes on one question — flag it and come back
  • Watch the timer — pace yourself (~1.5 minutes per question)
  • Don't second-guess too much — your first instinct is usually right
  • Answer every question — typically no penalty for guessing
  • For architecture questions: think about production implications, not just correctness
  • For "common mistake" questions: remember the anti-patterns (skipping history, ending loop early, "only if confident")
  • Review flagged questions if time allows

After the Exam

  • Note your score and any domain-specific feedback
  • If passed: download your certificate and digital badge immediately
  • Add the credential to your LinkedIn profile
  • Share your achievement on social media
  • If not passed: review the score breakdown by domain, study weak areas, schedule retake after waiting period

Section 11Frequently Asked Questions

Q: Do I need to pass CCAO-F or CCDV-F first before taking CCAR-F?

No. There are no formal prerequisites. However, Anthropic recommends having developer-level Claude experience. The knowledge builds on each level, so having working experience with the API, tool use, and agents is strongly recommended even if you skip the lower exams.

Q: Can I take it with a personal email (not a company account)?

Yes. The certification is an individual credential — it belongs to you, not your employer. Register with any personal email (Gmail, Outlook, etc.) and pay with a personal credit/debit card. No company sponsorship or corporate account needed.

Q: Do I need hands-on coding experience with the Claude API?

Strongly recommended. CCAR-F tests architectural concepts, not just theory. Questions involve code patterns (agentic loops, tool use, hooks), and understanding comes from building. At minimum, you should have built one tool-using agent and configured MCP before sitting the exam.

Q: What if I fail? How soon can I retake?

Typically 14-30 days waiting period. Use the time to study the domains where you scored lowest. An additional exam fee usually applies for the retake. Your score report will show domain-level breakdowns to guide your study.

Q: How is the CCAR-F different from the CCDV-F Developer exam?

CCDV-F tests building; CCAR-F tests designing. Developer: "How do I call the API, handle streaming, use tools?" Architect: "How do I design a multi-agent system, manage context at scale, implement guardrails, and make cost/latency trade-offs?" The Architect exam assumes you already know the Developer material and tests higher-level decision-making.

Q: Is the exam open-book or closed-book?

Typically closed-book. Online proctored exams don't allow notes, external resources, other browser tabs, or a second monitor. You need to know the material — not just where to find it. Check the specific exam policies when you register.

Q: How long is the certification valid?

Typically 2 years. You'll need to recertify as Claude's features, models, and best practices evolve. This ensures certified architects stay current with the platform.

Q: What roles benefit most from CCAR-F?

AI Solutions Architects, Senior Developers building multi-agent systems, Technical Leads making model selection decisions, Platform Engineers setting up Claude infrastructure, and GenAI Consultants advising clients. If you're designing systems (not just using Claude or writing API calls), this is your certification.

Q: What certifications complement CCAR-F well?

AWS AI/ML certifications (if deploying on Bedrock), Google Cloud AI certs (if on Vertex AI), Azure AI certifications (if on Foundry). Also: LangChain/LangGraph expertise, and domain-specific knowledge in your target industry (healthcare, finance, legal).

Q: What's the most important topic to study?

Domain 1: Agentic Architecture (~30% of the exam). Specifically: the agentic loop (how to branch on tool_use, append history correctly), the hub-and-spoke model (coordinator + workers), and common mistakes (skipping history, ending loop too early). This domain has the most questions and the trickiest scenarios.

Section 12Key Exam Topics — Quick Reference

The most heavily tested concepts to know cold:

Must KnowKey Fact
Agentic LoopAlways append assistant turn BEFORE tool_result. Check ALL content blocks for tool_use, not just the first.
Hub-and-SpokeSpokes have NO memory of the coordinator. Each spoke is a fresh API call with its own context window.
Stakes RuleHigh-stakes changes = more verification, less parallelism. Low-stakes = parallelize aggressively.
Prompts vs HooksPrompts are probabilistic (Claude might ignore). Hooks are deterministic (code always runs). Use both.
Tool DescriptionsThe "vs similar tools" clause is the most important part — tells Claude WHEN to use THIS tool vs alternatives.
Access vs Empty"You don't have access" ≠ "query returned no results." Claude needs different next steps for each.
CLAUDE.md HierarchyDeeper files override shallower ones. User → Project → Directory → Subdirectory.
Skills vs CLAUDE.mdCLAUDE.md loads automatically (always present). Skills load on demand (progressive disclosure saves tokens).
"Only if confident"Anti-pattern — Claude lacks calibrated uncertainty. Replace with explicit, objective match criteria.
Nullable FieldsUse "type": ["string", "null"] + "return null if unknown" to prevent fabricated data in structured output.
Lost in the MiddleLLMs attend strongly to beginning and end of context. Put key findings FIRST in tool results.
EscalationFrustration alone is NOT a valid trigger. Valid: human request, authority gap, verification flag, safety concern.
Retryable Errors429, 500, timeout = retry. 401, 400, 404 = DON'T retry (permanent failure). Check error type FIRST.
Tool Count5-15 tools per agent. More than 20 = split into specialized agents or use tool_search.
