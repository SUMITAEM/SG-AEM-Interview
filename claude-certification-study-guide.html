Part 01Anthropic & Claude Overview

What is Anthropic?

Anthropic is an AI safety company founded in 2021 that builds AI systems designed to be safe, beneficial, and understandable. Their flagship product is the Claude family of large language models.

Anthropic's Core Belief

"AI's impact could rival the industrial revolution, potentially arriving within a decade, but we aren't confident it will go well."

Part 06Tool Use & Function Calling

How Tool Use Works

The Tool Use Loop

1. Define tools (name, description, input_schema)
2. Send request → Claude returns tool_use block
3. Your code executes the tool
4. Send tool_result back to Claude
5. Claude formulates final response (or calls more tools)

Defining a Tool — Example

JSON — Tool Schema{ "name": "get_weather", "description": "Get the current weather for a location.", "input_schema": { "type": "object", "properties": { "location": { "type": "string", "description": "City and state, e.g. San Francisco, CA" } }, "required": ["location"] } }

Complete Tool Use — Python Example

Python# Step 1: Send request with tool definition response = client.messages.create( model="claude-opus-5-5", max_tokens=1024, tools=[weather_tool], tool_choice={"type": "auto"}, messages=[{"role": "user", "content": "What's the weather in SF?"}], ) # Step 2: Claude returns tool_use block tool_use = next(b for b in response.content if b.type == "tool_use") # tool_use.name = "get_weather" # tool_use.input = {"location": "San Francisco, CA"} # Step 3: Execute tool & send result back weather_data = "15°C, partly cloudy" # your lookup followup = client.messages.create( model="claude-opus-5-5", max_tokens=1024, tools=[weather_tool], messages=[ {"role": "user", "content": "What's the weather in SF?"}, {"role": "assistant", "content": response.content}, {"role": "user", "content": [ {"type": "tool_result", "tool_use_id": tool_use.id, "content": weather_data} ]}, ], )

Part 07Vision & Multimodal Capabilities

Supported Image Formats

JPEG, PNG, GIF, WebP. Animations unsupported (only first frame used). Claude cannot generate, edit, or create images — it is understanding only.

Image Limits

Max per API request (200K context)100 images

Visual Token Calculation

Formula

Visual tokens = ⌈width / 28⌉ × ⌈height / 28⌉

Each 28×28 pixel patch = 1 visual token. A 1000×1000 image = ~1,296 tokens.

Sending Images — Python Example

Python — URL Sourcemessage = client.messages.create( model="claude-opus-5-5", max_tokens=1024, messages=[{ "role": "user", "content": [ { "type": "image", "source": { "type": "url", "url": "https://example.com/photo.jpg" } }, {"type": "text", "text": "Describe this image."} ] }], )

Three image source types: base64, url, file (via Files API file_id).

Best Practice Place images before text in messages for best results. Use the Files API for repeated images to avoid re-sending base64 data every turn.

Part 08Thinking & Reasoning

How Thinking Works

When thinking is active, Claude works through the problem step-by-step before answering. The reasoning arrives in thinking content blocks ahead of the text response.

Two Thinking Modes

ModeConfigModelsBehavior
Adaptive{"type": "adaptive"}Claude 4.7+ (always on for 5.x)Claude decides when and how deeply to think. Steered by effort.
Extended{"type": "enabled", "budget_tokens": N}Haiku 4.5, older modelsManual mode with explicit budget. Deprecated on 4.6 models.

Configuring Thinking — Example

Pythonresponse = client.messages.create( model="claude-opus-5-5", max_tokens=16000, thinking={"type": "adaptive", "display": "summarized"}, messages=[{ "role": "user", "content": "What is the GCD of 1071 and 462?" }], ) for block in response.content: if block.type == "thinking": print(f"Thinking: {block.thinking}") elif block.type == "text": print(f"Answer: {block.text}")

Key Facts

  • Thinking tokens are billed as output tokens
  • They count toward max_tokens
  • display: "summarized" → visible reasoning text; "omitted" → empty thinking field
  • Thinking blocks carry a signature field — pass back unchanged in multi-turn conversations
  • Best for: math, coding, analysis, and agentic tasks

Part 09Prompt Engineering — Best Practices

The Five Core Principles

1. Be Clear and Direct

Example: Creating an Analytics Dashboard
Less Effective
Create an analytics dashboard
More Effective
Create an analytics dashboard. Include as many relevant features and interactions as possible. Go beyond the basics to create a fully-featured implementation.
Golden Rule

Show your prompt to a colleague with minimal context. If they'd be confused, Claude will be too.

2. Add Context and Motivation

Example: Formatting Constraint
Less Effective
NEVER use ellipses
More Effective
Your response will be read aloud by a text-to-speech engine, so never use ellipses since the TTS engine won't know how to pronounce them.

Claude generalizes from the WHY — it will also avoid other TTS-unfriendly characters.

3. Use Examples (Few-Shot Prompting)

Include 3–5 examples for best results. Make them:

  • Relevant — mirror your actual use case
  • Diverse — cover edge cases
  • Structured — wrap in <example> tags
Prompt Template<examples> <example> <input>What is 2+2?</input> <output>4</output> </example> <example> <input>What is the capital of France?</input> <output>Paris</output> </example> </examples> Now answer: <input>{{USER_QUESTION}}</input>

4. Structure with XML Tags

XML tags help Claude parse complex prompts unambiguously:

Structured Prompt<instructions> Summarize the document in 3 bullet points. Focus on key findings only. </instructions> <document> {{DOCUMENT_TEXT}} </document> <output_format> Return a JSON object with a "summary" array of 3 strings. </output_format>

5. Give Claude a Role

System Prompt// Set via the "system" parameter "You are a senior Python developer with 15 years of experience. You write clean, well-tested code and explain your decisions."

Advanced Techniques

Prompt Chaining

Break complex tasks into sequential sub-tasks. Output of step N becomes context for step N+1.

Structured Outputs

Two approaches: JSON output mode, or strict: true on tool definitions for validated schemas.

Long-Context Prompting

Place documents before queries. Use XML tags with index attributes for multiple docs.

Effort Parameter

Control thinking depth: low, medium, high. Not supported on Haiku 4.5.

Mnemonic: CERRS

Remember the 5 Principles

Clear and direct instructions
Examples (3-5, diverse, in XML tags)
Role in system prompt
Reasoning context (explain WHY)
Structure with XML tags

Part 10Safety, Ethics & Data Policies

Anthropic's Three Core Positions

1. Rapid Progress is Likely

Scaling laws show predictable capability improvement. Training costs remain far below major scientific projects.

2. Alignment is Unsolved

"No one knows how to train very powerful AI systems to be robustly helpful, honest, and harmless."

3. Empirical Research is Essential

Problems may only emerge at scale. Safety work must engage with frontier models.

Safety Research Portfolio

AreaDescription
Mechanistic InterpretabilityReverse-engineering neural networks to audit for unsafe behaviors
Scalable OversightUsing AI to help supervise AI training (Constitutional AI)
Process-Oriented LearningRewarding safe reasoning steps, not just outcomes
Understanding GeneralizationTracing how training data shapes emergent behaviors

Three Preparedness Scenarios

ScenarioAssumptionStrategy
OptimisticCurrent techniques largely sufficientContinue current approaches
IntermediateSignificant effort can prevent catastropheInvest heavily in safety research
PessimisticSafety may be unsolvableEvidence-gathering becomes critical

Anthropic hedges across all three rather than betting on one.

Data Retention & Privacy

Zero Data Retention (ZDR)

ZDR-Eligible
  • Context windows, thinking, vision
  • PDF support, citations, search results
  • Structured outputs, prompt caching
  • Client-side tools (bash, editor, computer use)
  • Token counting, web search*, web fetch*

*Except with dynamic filtering enabled

NOT ZDR-Eligible
  • Batch processing
  • Code execution
  • Files API
  • Agent Skills
  • MCP connector

Key Privacy Principles

  • Retained data is never used for model training without express permission
  • Anthropic designs for the smallest possible retention footprint
  • HIPAA-ready API access available (same eligibility as ZDR)
  • On partner platforms (Bedrock, Google Cloud), the cloud provider is the data processor
