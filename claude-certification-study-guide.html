Part 01Prompting and Task Execution

What Is a Prompt?

A prompt is the instruction you give to Claude to get a desired output. It can include context, examples, constraints, a question, a command, or any combination of these. Every interaction with Claude begins with a prompt — whether you type it into claude.ai, paste it into the Console playground, or send it via the API.

Think of a prompt as a brief to a smart colleague: the clearer and more specific your brief, the better the result. A prompt can be a single sentence ("Translate this to Spanish") or a multi-paragraph document with role definitions, reference data, examples, and format instructions.

Exam Tip The exam defines a prompt broadly: it is any instruction you give to Claude, and it can include context, examples, and constraints alongside the core task. Know that prompting is the single most important skill tested on the CCAO-F.

What Makes a Prompt Effective?

An effective prompt contains four key elements. Each one contributes to output quality:

ElementWhat It DoesExample
ContextBackground information that helps Claude understand the situation"We are a B2B SaaS company launching a new analytics feature next quarter."
RoleA persona or expertise level that primes Claude's tone and knowledge"You are a senior product marketing manager with 10 years of experience."
TaskThe specific action you want Claude to perform"Write a launch announcement email for our customer newsletter."
FormatThe desired structure, length, and style of the output"Use a subject line, 3 short paragraphs, and a CTA button text. Keep it under 200 words."

When all four elements are present, Claude has everything it needs to produce a high-quality, on-target response. Missing any one of these often leads to vague, off-format, or incomplete outputs.

The Golden Rule of Prompting

The Colleague Test

"Show your prompt to a colleague with minimal context. If they would be confused about what to do, Claude will be too." Clarity for a human equals clarity for Claude. If a coworker would ask "what exactly do you want me to do?", your prompt needs more specificity.

Using Examples in Prompts (Few-Shot Prompting)

Provide 3 to 5 examples of input/output pairs to show Claude exactly what you expect. Examples are more powerful than lengthy descriptions. Wrap them in <example> XML tags and make them relevant and diverse.

Returning it.</input> <output>NEGATIVE</output> </example> <example> <input>It's okay. Nothing special but it gets the job done.</input> <output>NEUTRAL</output> </example>

Structuring Prompts with XML Tags

Use XML tags like <instructions>, <context>, <input>, and <output_format> to organize your prompt. Claude is trained to recognize these structural boundaries, and structured prompts produce significantly better results than unstructured walls of text.

Structured Prompt Template <instructions> You are a contract analyst. Extract key terms from the provided agreement and present them in a table. </instructions> <context> This is a vendor services agreement for a SaaS platform. The legal team needs a quick summary before the review meeting. </context> <input> {{CONTRACT_TEXT_HERE}} </input> <output_format> Return a table with columns: Clause | Summary | Risk Level (Low/Medium/High) </output_format>

What Is Task Decomposition?

Task decomposition means breaking a complex request into smaller, manageable steps that Claude can handle one at a time. Instead of asking Claude to do everything in one prompt, you split the work into a sequence of focused sub-tasks.

Task Decomposition Example
One Monolithic Prompt
"Write a complete marketing plan for our new fitness app."
Decomposed Into Steps
Step 1: "Research and define our target audience demographics for a fitness app aimed at busy professionals."
Step 2: "Based on this audience, define 3 measurable marketing goals for the first quarter."
Step 3: "Draft messaging and positioning statements for each goal."
Step 4: "Review the full plan for consistency and suggest improvements."

Decomposition works because Claude produces higher-quality output when focused on one task at a time. Each step builds on the previous one, and you can review and correct at each stage.

What Is Prompt Iteration?

Prompt iteration is the process of refining your prompt based on the quality of Claude's output. Rarely is the first prompt perfect. The cycle is:

  1. Run your initial prompt and review the output
  2. Evaluate what is wrong or missing (too long? wrong format? hallucinated facts? off-topic?)
  3. Refine the prompt by adding specificity, examples, or constraints to address the gaps
  4. Re-test with the improved prompt and compare results

Iterating a Prompt to Improve Output Quality

Here is a concrete example showing how a prompt evolves through three iterations:

Prompt Iteration: v1 to v3

"Summarize this report."
Result: A 500-word general summary that misses the financial highlights the CFO needs.
Version 2 (Adding Constraints)

Defined Constraints

Constraints are boundaries you set for the task. They help Claude produce output that matches your exact needs.

  • Length: "Respond in under 200 words" or "Write exactly 5 bullet points"
  • Format: "Return as a numbered list" or "Use a markdown table"
  • Tone: "Use a formal business tone" or "Write in a friendly, conversational style"
  • Audience: "This is for a C-level executive" or "Explain to a non-technical reader"
  • Scope: "Only use information from the provided document" or "Do not include external sources"

Multi-Turn Conversations

In multi-turn conversations, Claude retains context from previous messages within the same conversation. You can build on earlier responses, ask follow-up questions, or refine outputs incrementally. Key techniques:

  • Reference previous output: "In your analysis above, expand on point 3 with more detail."
  • Add new constraints: "Now rewrite that summary for a non-technical audience."
  • Course-correct: "That's too detailed. Give me the top 3 points only."
  • Build incrementally: "Good outline. Now write the full first section."

Common Prompting Mistakes

Vague Instructions

Telling Claude to "help with marketing" without specifying the task, audience, or format. Fix: add all four elements (context, role, task, format).

No Examples

Expecting Claude to match a very specific output style without showing what it looks like. Fix: provide 3-5 representative examples.

Missing Constraints

Not specifying length, format, or tone — leading to outputs that are too long, too short, or off-target. Fix: be explicit about format and boundaries.

Overloading a Single Prompt

Asking Claude to do five unrelated tasks in one prompt. Fix: decompose into sequential focused prompts.

Part 02Output Evaluation and Validation

What Is a Hallucination?

A hallucination is when Claude generates plausible-sounding but factually incorrect information. The output sounds confident and authoritative, but the facts are wrong. Claude does not "know" it is wrong — it generates text that is statistically likely given the context, which sometimes means inventing details.

Example: Claude might cite "a 2023 study by Dr. Sarah Chen at MIT" that does not exist. The citation looks real, follows proper formatting, and supports the argument — but the paper, the author, and the findings are all fabricated.

Key Risk Hallucinations are especially dangerous because they look correct. Common hallucination targets: specific numbers, dates, URLs, academic citations, legal statutes, and person biographies. Always verify these.

What Is Bias in AI Output?

Bias in AI output is systematic skew that reflects patterns in training data. It can be cultural, demographic, or topical. Biased output may present one-sided perspectives, use stereotypical language, or systematically favor one group over another.

How to spot bias:

  • Ask Claude to present multiple perspectives on a topic and check if one is given more weight
  • Look for one-sided framing (e.g., only positive aspects of a technology, only negative aspects of a policy)
  • Test with diverse inputs (different demographics, regions, viewpoints) and check if outputs are consistently balanced
  • Watch for stereotypical associations in generated content

What Are Inconsistencies and Factual Errors?

Inconsistencies are contradictions within the same response. Factual errors are statements that contradict known, verifiable facts.

Inconsistency example: Claude says "Acme Corp was founded in 2010" in paragraph one and "since its founding in 2012, Acme Corp has grown..." in paragraph three. Both cannot be true.

Factual error example: Claude states "Paris is the capital of Germany." This is straightforwardly false regardless of context.

Both types of errors undermine trust in the output and require systematic checking.

What Do "Accuracy" and "Completeness" Mean for an Output?

  • Accuracy = the facts in the output are correct. Every claim, number, date, and attribution can be verified against authoritative sources.
  • Completeness = all requested elements are present and nothing important is omitted. If you asked for 5 bullet points covering revenue, churn, and growth, you should get all 5 points and all 3 topics.

An output can be accurate but incomplete (all facts are correct, but it only covers 2 of 5 requested topics) or complete but inaccurate (all topics are covered, but some facts are wrong). The best output is both.

What Is Fact-Checking and Validation?

Fact-checking is the process of cross-referencing Claude's claims against authoritative sources — official documentation, databases, expert knowledge, or primary sources. Validation means systematically verifying that the output meets your requirements.

This is not asking Claude "is this correct?" — Claude may confidently restate incorrect information. True fact-checking requires checking against external sources independent of Claude.

When Is Human Review or Extra Verification Required?

Human review is required when:

  • High-stakes decisions: Medical, legal, financial, or safety-critical information
  • Public-facing content: Marketing materials, press releases, official communications
  • Regulated industries: Healthcare (HIPAA), finance (SOX), legal compliance
  • Data affecting people's lives: Hiring decisions, credit assessments, academic evaluations
  • Specialized domains: Areas requiring deep expertise that you cannot independently verify

Artifacts

Standalone documents, code files, or visualizations that Claude creates in a separate panel on claude.ai. Can be iterated, downloaded, and shared. Best for longer-form content you want to save or reuse.

Spotting Hallucinations, Inconsistencies, and Bias

Practical techniques for detecting each type of problem:

  • Hallucinations: Ask Claude to cite its sources. If it cites a specific paper, URL, or statistic, verify it exists. Add "only use information from the provided document" to prevent Claude from inventing facts.
  • Inconsistencies: Read the full response and check for contradictions. Pay special attention to numbers, dates, and names that appear more than once — they should match each time.
  • Bias: Look for one-sided framing. Ask Claude to argue the opposite perspective. Check if recommendations systematically favor a particular demographic, technology, or viewpoint without justification.

Validation Strategies

  • Cross-reference with source documents: If you gave Claude a report to summarize, verify the summary against the original
  • Consistency checks across multiple runs: Run the same prompt several times — if answers differ significantly on factual questions, the prompt needs improvement
  • Human-in-the-loop review: For critical outputs (legal, medical, financial), always have a qualified human review before acting on Claude's response
  • Chained verification: Ask Claude to verify its own output — "Review your response above and identify any claims not directly supported by the provided document"

Fact-Checking Claims and Citations Against Authoritative Sources

Follow this process for systematic fact-checking:

  1. Identify key claims — extract every factual statement, statistic, date, and attribution
  2. Find authoritative sources — official documentation, government databases, peer-reviewed research, company reports
  3. Verify each claim — confirm the fact matches the source exactly
  4. Flag discrepancies — mark any claim that cannot be verified or that contradicts the source
  5. Decide action — correct the errors, remove unverifiable claims, or add appropriate caveats

Deciding When to Escalate to Human Review

Escalation Decision Framework
  • Is it high-stakes? If errors could cause financial loss, legal liability, health risks, or reputational damage — escalate to a qualified expert.
  • Is the domain specialized? If you lack the expertise to judge correctness (e.g., medical, legal, engineering) — escalate to a domain expert.
  • Am I confident in the facts? If you cannot independently verify key claims — escalate or flag as unverified.
  • Is it going external? If customers, regulators, or the public will see it — escalate to appropriate reviewers.

Editing and Adapting Output for a Specific Audience

Claude's raw output may need adjustment for different audiences. Consider:

  • Technical vs. non-technical: Remove jargon for executive summaries; add technical detail for engineering teams
  • Internal vs. external: Internal drafts can be candid; external communications need polish and diplomatic framing
  • Complexity level: Adjust reading level — a CEO summary is different from a detailed analyst report
  • Length: Board decks need brevity; reference documents need thoroughness
  • Tone: Formal for legal/compliance, conversational for marketing, empathetic for customer support

Comparing and Refining Multiple Outputs

For important tasks, generate 2-3 versions and select the best elements from each:

  1. Run the same prompt (or slightly varied prompts) 2-3 times
  2. Evaluate each version against your criteria (accuracy, completeness, tone, format)
  3. Identify the strongest elements from each version
  4. Combine the best elements into a final version, or use the strongest version as a starting point
  5. Refine the combined version for consistency

Feedback Loops

Use evaluation results to improve your prompts iteratively. If Claude consistently gets a certain type of question wrong, add examples of that type to your prompt. If outputs are too verbose, add explicit length constraints. Document what worked and what didn't to build a library of effective prompts for your use cases.

Part 03Product and Model Selection

Claude's Product Features: Chat, Projects, Research Mode, and Artifacts

Chat

The conversational interface at claude.ai for quick tasks. Upload files, ask questions, get answers. No setup required — just open your browser and start typing.

Projects

Organize related conversations with shared instructions and uploaded knowledge files. All conversations within a project share the same context. Ideal for ongoing work.

Research Mode

Claude autonomously searches the web, reads multiple sources, and synthesizes a comprehensive cited report. Use for deep investigation where you need Claude to gather information on its own.

Artifacts

Standalone documents, code, spreadsheets, or visualizations created in a dedicated panel. Can be iterated, shared, and downloaded. Great for longer-form content creation.

What Is a Claude Project?

A Project is a persistent workspace in claude.ai with shared instructions and uploaded files that apply across all conversations within the project. Think of it as a "custom Claude" — you define the role, policies, and reference knowledge once, and every new conversation inherits that context automatically.

Projects are the simplest way for non-developers to create a tailored Claude experience without writing code. Common examples: a customer support project with company policies, a content creation project with brand guidelines, a research project with domain-specific documents.

What Is Research Mode?

Research mode enables Claude to autonomously search the web, read multiple sources, and produce a comprehensive, cited research report. You give Claude a research question, and it plans a search strategy, visits relevant pages, synthesizes findings, and presents a report with citations.

Best for: competitive analysis, market research, literature reviews, fact-finding on current topics, and any task where Claude needs to gather information from external sources.

What Are Artifacts?

Artifacts are standalone pieces of content — documents, code files, diagrams, spreadsheets, interactive visualizations — that Claude creates in a dedicated side panel on claude.ai. Unlike inline responses, artifacts can be:

  • Iterated and refined through follow-up prompts
  • Downloaded as files
  • Shared with others via a link
  • Used as a starting point for further work

What Are Claude Skills?

Skills are pre-built capabilities that enable Claude to create specific types of content: presentations (slides), spreadsheets, formatted documents, and more. Skills extend what Claude can produce beyond plain text, allowing it to generate ready-to-use business deliverables.

What Is Code Execution?

Code Execution allows Claude to run Python code in a secure sandbox environment. Claude can write and execute code to analyze data, create charts and visualizations, process files, and perform calculations. The results (including generated charts) are returned directly in the conversation.

This is especially powerful for data analysis tasks where you need Claude to work with actual numbers rather than just describe what it would do. Example use cases:

  • Upload a CSV and ask Claude to calculate averages, find outliers, or create a chart
  • Ask Claude to process a spreadsheet and generate summary statistics
  • Have Claude create data visualizations from your raw data
  • Run mathematical calculations that require precision

What Is a Context Window / Context Limit?

The context window is Claude's working memory — everything it can reference in a single conversation. This includes the system prompt, all previous messages, uploaded documents, and Claude's own responses. It is NOT training data.

  • 1M tokens (approximately 555,000 words) for Sonnet 5, Opus 5.5, and Fable 5.1
  • 200K tokens (approximately 150,000 words) for Haiku 4.5
  • When the context fills up, you need to start a new conversation or summarize earlier content
  • Claude does NOT remember previous conversations — each one starts fresh

What Is Memory, and When to Restart, Summarize, or Persist?

Restart

When the topic completely changes, when context is polluted with irrelevant information, or when Claude starts referencing earlier mistakes. A fresh conversation gives Claude a clean slate.

Summarize

Ask Claude to summarize the key points and decisions so far. Copy-paste the summary into a new conversation. This preserves essential context while freeing up the context window.

Persist (Projects)

Use Projects to maintain context across conversations. Upload reference documents and set persistent instructions that apply to every new conversation in the project.

Managing Context Limits: When to Restart, Summarize, or Persist

Practical strategies for working within context limits:

  • Monitor conversation length: If responses start degrading in quality or referencing earlier errors, the context may be getting crowded
  • Prioritize relevant content: Only include documents and information that are directly relevant to the current task
  • Use the summarize-and-restart pattern: Ask Claude to produce a concise summary of progress, then start fresh with that summary
  • Leverage Projects: Upload reference docs to a project so they persist without eating into each conversation's context window
  • Break large documents: For very large files, consider processing them in sections rather than uploading everything at once

Pricing Awareness

Claude pricing is based on tokens — units of text (roughly 4 characters or 3/4 of a word). Pricing is quoted per million tokens (MTok). Input tokens (what you send) are cheaper than output tokens (what Claude generates). Key cost-saving strategies:

  • Use the right model: Don't use Fable for a simple summarization — Sonnet or Haiku will do at a fraction of the cost
  • Prompt caching: Reuse repeated prompt prefixes to reduce input costs by up to 90%
  • Batch processing: For non-urgent bulk tasks, Batch API saves 50% on all token costs
  • Shorter prompts: Trim unnecessary context — every token costs money

Part 04Workflow Integration and Solution Design

What Is a Workflow?

A workflow is a sequence of steps to accomplish a business process. It can be manual (humans do each step), automated (systems do each step), or hybrid (a mix of human and automated steps). In the context of the CCAO-F exam, a workflow is any repeatable business process where Claude can play a role.

Examples: customer onboarding, content review and publication, support ticket resolution, employee training material creation.

What Does Process Optimization with AI Mean?

Process optimization means identifying bottlenecks, inefficiencies, or high-effort steps in existing workflows where Claude can save time, improve quality, or reduce cost. The key steps are:

  1. Map your current workflow (document every step and who does it)
  2. Identify the most time-consuming or error-prone steps
  3. Assess which of those steps Claude can handle (text-based tasks, analysis, drafting)
  4. Estimate the time/cost savings from automating or augmenting those steps
  5. Implement with human oversight and measure results

Integrating Claude into a Workflow: Augment vs. Redesign

Augment (Add to Existing Steps)

Keep your existing process and add Claude to specific steps. Example: Claude drafts the initial email, but a human reviews and sends it. The workflow stays the same — Claude just makes one step faster.

What Are Project Instructions?

Project instructions are persistent instructions that apply to every conversation within a Claude Project. They function like a system prompt for the entire project — defining Claude's role, tone, constraints, and reference knowledge that carries across all conversations. When you start a new conversation in a project, those instructions are automatically included.

Example: "You are a customer support agent for Acme Software. Always be professional and empathetic. Refer to the company policies document for refund and pricing questions. Never promise features that are not currently available."

What Is a Knowledge Source (Uploaded Files)?

Knowledge sources are files you upload to a Claude Project — PDFs, documents, spreadsheets, text files — that Claude can reference when answering questions. They become part of the project's context, available to every conversation.

  • Supported formats: PDF, Word docs, text files, CSV, Excel, images
  • Claude can read text content and analyze visual elements (charts, diagrams)
  • Files are subject to context window limits — very large file sets may not all fit
  • Uploaded files are not used to train the model — they only exist within your project context

What Are Connectors: Google Drive and Gmail?

Connectors are integrations that let Claude access your Google Drive files and Gmail messages directly, without requiring manual file uploads. This means Claude can:

  • Search and read documents stored in your Google Drive
  • Reference Gmail conversations for context
  • Stay current with the latest versions of shared documents
  • Reduce the manual effort of uploading and re-uploading files

Connectors are available on Team and Enterprise plans and require appropriate permissions to be configured.

What Are System-Level Instructions?

System-level instructions (also called system prompts) control Claude's behavior across the entire conversation. They are set before the first user message and define persistent rules. Key uses:

  • Role: "You are a financial analyst" (sets expertise and tone)
  • Format: "Always respond with a summary table followed by key takeaways" (sets structure)
  • Constraints: "Never provide medical advice" or "Only use information from provided documents" (sets boundaries)
  • Examples: Include few-shot examples in the system prompt for consistent classification/categorization

Part 07Troubleshooting and Optimization

What Does an Underperforming Prompt or Poor Output Look Like?

Recognizing poor output is the first step to fixing it. Common symptoms of an underperforming prompt:

  • Too vague: The response is generic and doesn't address your specific situation
  • Too long: Claude provides a 1000-word essay when you needed 3 bullet points
  • Wrong format: You asked for a table and got paragraphs
  • Missing key info: The response skips critical elements you asked for
  • Hallucinations: The output contains fabricated facts, citations, or statistics
  • Off-topic: Claude answers a different question than the one you asked
  • Inconsistent tone: The language shifts between formal and casual within the same response
  • Repetitive: The same point is restated in different words throughout the response

What Is Troubleshooting an AI Output?

Troubleshooting is the systematic process of diagnosing why an output is poor and fixing the root cause. The process is:

  1. Identify the problem — what specifically is wrong? (too vague? wrong format? hallucinating?)
  2. Check the prompt — does the prompt clearly specify what you want, in what format, with what constraints?
  3. Test variations — change one element at a time (add examples, add constraints, change wording)
  4. Iterate — run the improved prompt and compare results to the original
  5. Resolve — once the output meets your requirements, document what worked for future use

What Is Workflow Optimization?

Workflow optimization means improving the efficiency of Claude-integrated workflows. This goes beyond individual prompts to consider the entire process:

  • Reducing the number of steps needed to get a quality result
  • Choosing the right model for each task (cost vs. quality tradeoff)
  • Using Projects for persistent context instead of re-uploading documents
  • Batching similar tasks for efficiency
  • Using Research mode for tasks that need web information

Debugging Techniques

  1. Change one thing at a time: When iterating on a prompt, change only one element per attempt so you can identify what helps vs. what hurts.
  2. Test with edge cases: Try unusual inputs, very long texts, ambiguous requests, and adversarial inputs to stress-test your prompt.
  3. Compare models: Run the same prompt on different models — if Haiku fails but Sonnet succeeds, the task may need more reasoning capability.
  4. Simplify first: If a complex prompt fails, strip it down to essentials and add elements back one by one until you find the problem.
  5. Check the format: Ensure your prompt doesn't have ambiguous structure. Use XML tags to clearly separate instructions from data.

Prompt Caching and Batch Processing Basics

How Prompt Caching Works

When you send the same prompt prefix repeatedly (e.g., a long system prompt with policies and examples), caching stores it so subsequent requests only pay a fraction of the input cost.

  • 5-minute cache: Write cost = 1.25x input. Read cost = 10% of input. Pays off after just 1 read.
  • 1-hour cache: Write cost = 2x input. Read cost = 10% of input. Pays off after 2 reads.
  • Best for: system prompts, few-shot examples, and large context blocks that repeat across requests.

Correct: C. Model optimization means using the cheapest model that meets quality requirements. If a simple classification task works well with Opus, it likely works just as well with Sonnet or Haiku at a fraction of the cost. Always test a cheaper model first.
