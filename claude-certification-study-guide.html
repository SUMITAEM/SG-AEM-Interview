Part 01Prompting and Task Execution

What Is a Prompt?

A prompt is the instruction you give to Claude to get a desired output. It can be a question, a command, a set of instructions, or a combination of all three. Every interaction with Claude begins with a prompt — whether you type it into claude.ai, paste it into the Console playground, or send it via the API.

Prompting is the single most important skill for the CCAO-F exam. The quality of Claude's output is directly determined by the quality of your prompt.

Claude's Interaction Model

Claude conversations are structured around three message roles:

RolePurposeExample
System PromptPersistent instructions that define Claude's behavior across the entire conversation"You are a helpful financial analyst. Always provide data in tables."
User MessageYour actual question or instruction"Summarize Q3 revenue by region."
Assistant ResponseClaude's outputThe summary table Claude generates

The Golden Rule of Prompting

The Colleague Test

"Show your prompt to a colleague with minimal context. If they would be confused about what to do, Claude will be too." Clarity for a human equals clarity for Claude.

Five Core Prompting Principles

1. Be Clear and Direct

Give specific instructions. State the desired format, constraints, and output structure. Do not assume Claude will infer what you want.

Principle 1 — Be Clear and Direct
Vague Prompt
"Create an analytics dashboard."
Clear Prompt
"Create an analytics dashboard with user engagement metrics, revenue trends, and conversion funnels. Include filters for date range and region. Present the data as a summary table followed by key takeaways in bullet points."

2. Add Context and Motivation

Explain why you need the output, not just what you need. When Claude understands the purpose, it makes better decisions about format, tone, and depth.

Principle 2 — Add Context and Motivation
No Context
"NEVER use ellipses."
With Context
"Your response will be read aloud by a text-to-speech engine, so never use ellipses since the engine won't know how to pronounce them. Also avoid abbreviations for the same reason."

3. Use Examples (Few-Shot Prompting)

Provide 3-5 examples of input/output pairs. Examples are more powerful than lengthy descriptions. Wrap them in <example> XML tags and make them relevant and diverse.

Prompt with Examples <!-- System prompt with few-shot examples --> Classify each customer review as POSITIVE, NEGATIVE, or NEUTRAL. <example> <input>The product arrived on time and works great!</input> <output>POSITIVE</output> </example> <example> <input>Completely broken out of the box. Returning it.</input> <output>NEGATIVE</output> </example> <example> <input>It's okay. Nothing special but it gets the job done.</input> <output>NEUTRAL</output> </example>

4. Structure with XML Tags

Use XML tags like <instructions>, <context>, <input>, and <output> to organize your prompt. Claude is trained to recognize these structural boundaries, and structured prompts produce significantly better results.

Structured Prompt Template <instructions> You are a contract analyst. Extract key terms from the provided agreement and present them in a table. </instructions> <context> This is a vendor services agreement for a SaaS platform. The legal team needs a quick summary before the review meeting. </context> <input> {{CONTRACT_TEXT_HERE}} </input> <output_format> Return a table with columns: Clause | Summary | Risk Level (Low/Medium/High) </output_format>

5. Give Claude a Role

Set a persona in the system prompt to prime Claude's expertise and communication style. Roles significantly improve domain-specific outputs.

Principle 5 — Assign a Role
No Role
"Help me analyze my investment portfolio."
With Role
"You are a senior financial analyst with 20 years of experience in portfolio management. Analyze the following investment portfolio. Focus on diversification gaps, risk exposure, and recommend rebalancing strategies. Present findings in a professional report format."

Task TypeDescriptionExample Prompt
SummarizationCondense long content"Summarize this quarterly report in 5 bullet points focusing on revenue growth."

Defined Constraints

Constraints are boundaries you set for the task. They help Claude produce output that matches your exact needs.

  • Length: "Respond in under 200 words" or "Write exactly 5 bullet points"
  • Format: "Return as a numbered list" or "Use a markdown table"
  • Tone: "Use a formal business tone" or "Write in a friendly, conversational style"
  • Audience: "This is for a C-level executive" or "Explain to a non-technical reader"
  • Scope: "Only use information from the provided document" or "Do not include external sources"

Iterative Prompting

Rarely is the first prompt perfect. Iterative prompting means refining your prompt based on Claude's output quality:

  1. Write your initial prompt and review the output
  2. Identify gaps — is it too long? Too vague? Wrong format?
  3. Add missing constraints, examples, or context
  4. Re-run and compare
  5. Repeat until output quality meets your needs

Multi-Turn Conversations

In multi-turn conversations, Claude retains context from previous messages. You can build on earlier responses, ask follow-up questions, or refine outputs incrementally. Key tips:

  • Reference previous output: "In your analysis above, expand on point 3."
  • Add new constraints: "Now rewrite that summary for a non-technical audience."
  • Course-correct: "That's too detailed. Give me the top 3 points only."

Prompt Templates and Reusability

For recurring tasks, create prompt templates with placeholders. This ensures consistency and saves time.

Template Example <instructions> Summarize the following {{DOCUMENT_TYPE}} for the {{TARGET_AUDIENCE}} team. Focus on {{FOCUS_AREAS}}. Keep the summary to {{MAX_LENGTH}} words. </instructions> <document> {{DOCUMENT_CONTENT}} </document>

Common Prompting Mistakes

Vague Instructions

Telling Claude to "help with marketing" without specifying the task, audience, or format.

No Examples

Expecting Claude to match a very specific output style without showing what that style looks like.

Missing Constraints

Not specifying length, format, or tone — leading to outputs that are too long, too short, or off-target.

Overloading a Single Prompt

Asking Claude to do five unrelated tasks in one prompt. Break complex requests into steps.

Exam Tip Prompting is the largest section on the CCAO-F exam. Know the five core principles by heart, and be able to identify good vs. bad prompts in multiple-choice scenarios.

Part 02Output Evaluation and Validation

Why Evaluate Outputs?

Claude can produce impressive-sounding text that is factually wrong, incomplete, or off-format. Output evaluation is the process of systematically checking Claude's responses against your requirements. Without evaluation, you risk using hallucinated facts, inconsistent formatting, or missing critical information.

Manual Evaluation Techniques

CheckWhat to Look ForHow to Apply
AccuracyAre the facts correct?Cross-reference claims with source documents or known data
CompletenessDoes it cover all required points?Compare output against your prompt requirements one by one
Format ComplianceDoes it match the requested format?Check for correct structure (table, list, JSON, etc.)
Tone/StyleIs it appropriate for the audience?Read as if you are the intended recipient
ConsistencyDoes the response contradict itself?Look for conflicting statements within the same output

Automated Evaluation Approaches

Exact Match

For categorical or classification outputs, compare Claude's answer to the known correct answer character-for-character. Best for tasks with definitive right answers (e.g., "Is this email spam? YES/NO").

Semantic Similarity

Compare the meaning of Claude's output against a reference answer, not the exact words. Useful when multiple phrasings can be correct. Often uses embedding-based similarity scores.

LLM-as-Judge

Use Claude itself (or another model) to evaluate output quality. Provide a rubric and ask the judge model to rate the response on a Likert scale (1-5) across dimensions like accuracy, helpfulness, and clarity.

LLM-as-Judge Prompt Rate the following response on a scale of 1-5 for each criterion: <criteria> - Accuracy: Are all facts correct? (1=many errors, 5=fully accurate) - Completeness: Does it address all parts of the question? (1=missing most, 5=complete) - Clarity: Is it easy to understand? (1=confusing, 5=crystal clear) </criteria> <response_to_evaluate> {{CLAUDE_OUTPUT}} </response_to_evaluate> Provide your scores as a JSON object with brief justifications.

Binary Checks

Simple yes/no validations: Does the output contain PII? Is it toxic? Does it mention competitors? These can be automated as guard-rails before showing output to end users.

Validation Strategies

  • Cross-reference with source documents: If you gave Claude a report to summarize, verify the summary against the original document
  • Consistency checks across multiple runs: Run the same prompt several times — if answers differ significantly on factual questions, the prompt needs improvement
  • Human-in-the-loop review: For critical outputs (legal, medical, financial), always have a qualified human review before acting on Claude's response
  • Chained verification: Ask Claude to verify its own output — "Review your response above and identify any claims that are not directly supported by the provided document"

Red Flags in Claude's Outputs

Confident but Wrong (Hallucination)

Claude states a fact with certainty that turns out to be incorrect. Common with specific numbers, dates, URLs, and citations.

Overly Verbose or Generic

The response is long and sounds good but doesn't actually answer your specific question. Often a sign the prompt was too vague.

Missing Requested Elements

You asked for 5 bullet points and got 3, or asked for a table and got prose. Indicates the prompt needs clearer format constraints.

Internal Contradictions

Claude says "revenue increased by 15%" in one paragraph and "revenue was flat" in another. Cross-check all claims.

Output Quality Metrics

MetricDefinitionHow to Measure
AccuracyFactual correctness of the responseHuman verification or fact-checking against sources
RelevanceHow well the response addresses the actual questionDoes it answer what was asked, not something adjacent?
CoherenceLogical flow and readabilityRead aloud — does it make sense from start to finish?
CompletenessCovers all required aspects of the taskChecklist against prompt requirements

Feedback Loops

Use evaluation results to improve your prompts iteratively. If Claude consistently gets a certain type of question wrong, add examples of that type to your prompt. If outputs are too verbose, add explicit length constraints. Document what worked and what didn't to build a library of effective prompts for your use cases.

When to Trust vs. Verify

Trust vs. Verify Decision Framework
  • High trust, minimal verification: Creative brainstorming, first drafts, idea generation, casual summaries
  • Moderate trust, spot-check: Email drafts, meeting notes, general analysis, non-critical content
  • Low trust, full verification: Financial figures, legal clauses, medical information, data-driven decisions, anything published externally
  • Never trust without expert review: Medical diagnosis, legal advice, safety-critical systems, compliance decisions

Pricing Awareness

Claude pricing is based on tokens — units of text (roughly 4 characters or 3/4 of a word). Pricing is quoted per million tokens (MTok). Input tokens (what you send) are cheaper than output tokens (what Claude generates). Key cost-saving strategies:

  • Use the right model: Don't use Fable for a simple summarization — Sonnet or Haiku will do at a fraction of the cost
  • Prompt caching: Reuse repeated prompt prefixes to reduce input costs by up to 90%
  • Batch processing: For non-urgent bulk tasks, batch API saves 50% on all token costs
  • Shorter prompts: Trim unnecessary context — every token costs money

Integrating Claude into Business Workflows

Claude becomes most valuable when integrated into existing business processes rather than used in isolation. The goal is to identify repetitive, knowledge-intensive tasks where Claude can save time while maintaining quality through human oversight.

Common Integration Patterns

PatternDescriptionExample
Human-in-the-LoopClaude drafts, human reviews and approvesClaude drafts customer emails, agent reviews before sending
Automated PipelineClaude processes data in batch without human review per itemClassify 10,000 support tickets overnight
Conversational InterfaceClaude powers a chatbot for customers or internal teamsIT helpdesk bot that answers common questions

Workflow Design Principles

Four Principles for Workflow Design
  • Start simple, iterate: Begin with one task, prove value, then expand
  • Define clear inputs and outputs: Specify exactly what goes into each step and what comes out
  • Plan for failure modes: What happens if Claude gives a wrong output? Build fallbacks
  • Monitor and measure quality: Track accuracy, speed, and cost over time

Solution Design Patterns

Single-Shot

One prompt, one response. Best for straightforward tasks like Q&A, summarization, or simple classification.

Multi-Turn

A conversation with follow-ups. Best for customer support, tutoring, or iterative analysis where context builds over time.

Prompt Chaining

Break a complex task into sequential steps where the output of one step becomes the input for the next. This improves quality by letting Claude focus on one thing at a time.

Prompt Chaining Example Step 1: Extract key facts from this document. --> Output: list of facts Step 2: Organize these facts into categories. --> Output: categorized facts Step 3: Write an executive summary using the categorized facts. Keep it under 300 words. --> Output: polished summary

Fan-Out

Process multiple items in parallel. Best for batch tasks like classifying hundreds of documents or generating product descriptions for a catalog.

Router

Classify the input first, then route it to a specialized prompt. For example, classify a customer inquiry as billing, technical, or general, then use a different prompt template for each category.

Knowledge Management

System Prompts as Knowledge Containers

System prompts can embed company policies, style guides, product information, and domain expertise. This "primes" Claude with the knowledge it needs for your specific use case. Structure the knowledge with XML tags for clarity.

Knowledge-Rich System Prompt You are a customer support agent for Acme Software. <company_policies> - Refund window: 30 days from purchase - Free tier: 5 projects, 1GB storage - Pro tier: unlimited projects, 100GB storage, priority support - Enterprise: custom pricing, SLA, dedicated account manager </company_policies> <tone_guidelines> - Professional but friendly - Use the customer's first name - Acknowledge frustration before offering solutions - Never promise features that don't exist </tone_guidelines>

Context Window as Working Memory

The context window is everything Claude can reference during a conversation — all previous messages, system prompt, and uploaded documents. It is NOT training data. Think of it as Claude's "desk" — what's currently in front of it. Key facts:

  • 1M tokens for Fable, Opus, and Sonnet (~750,000 words)
  • 200K tokens for Haiku (~150,000 words)
  • When the window fills up, oldest messages may be trimmed
  • Claude does not remember previous conversations (no persistent memory by default)

Uploading Documents

In claude.ai and via the API, you can upload files for Claude to analyze:

  • PDFs: Claude can read text and analyze visual content (charts, diagrams)
  • Images: JPEG, PNG, GIF, WebP — Claude describes, analyzes, and extracts information from images
  • Text files: Plain text, CSV, code files
  • Spreadsheets: Excel files for data analysis

Projects in claude.ai

Projects provide shared instructions and uploaded knowledge that persist across multiple conversations. They are the simplest way to create a "custom Claude" without code. A project can include:

  • A custom system prompt (project instructions)
  • Uploaded reference documents (PDFs, text files)
  • Multiple conversations that all share the same context

Best Practices for Knowledge Management

Keep System Prompts Focused

Don't dump everything into one system prompt. Organize by purpose: role, policies, format rules, constraints.

Use XML Tags for Structure

Separate different types of knowledge with XML tags so Claude can distinguish instructions from reference material.

Update Knowledge Regularly

Claude has a training data cutoff. If your policies or products change, update the system prompt and uploaded documents.

Separate Instructions from Data

Put "what to do" in one section and "reference material" in another. This prevents Claude from confusing the two.

Limitations to Know

Key Limitations Context window limits: Even with 1M tokens, very large document sets may not fit. Prioritize the most relevant content.
Knowledge cutoff: Claude doesn't know about events after its training data cutoff date. Always provide current information in the prompt for time-sensitive tasks.
No persistent memory: Each conversation starts fresh unless you use Projects to carry over context. Claude does not "learn" from your previous conversations.

Vision Capabilities

Claude can analyze images uploaded directly in claude.ai or sent via the API. Supported formats include JPEG, PNG, GIF, and WebP. Use cases include:

  • Describing and interpreting charts, graphs, and diagrams
  • Extracting text from screenshots or photos (OCR-like behavior)
  • Analyzing product images, UI mockups, or design documents
  • Comparing multiple images for differences

PDF Processing

Claude can read both the text content and visual elements of PDF documents. It can summarize multi-page reports, extract key data from forms, and answer questions about the content. For large PDFs, consider breaking them into sections and processing each separately.

Part 06Governance, Risk, and Responsible Use

Anthropic's AI Safety Philosophy

Anthropic was founded on the belief that AI will be transformative and that safety must be a core priority, not an afterthought. Their approach rests on three core positions:

Rapid Progress Is Likely

AI capabilities are advancing quickly. Anthropic believes transformative AI could arrive within the next decade, making safety research urgent.

Alignment Is Unsolved

There is no proven way to guarantee that powerful AI systems will behave as intended. Research is needed to solve this problem before it becomes critical.

Empirical Research Is Essential

Safety cannot be solved theoretically alone. Building and testing AI systems provides the data needed to develop practical safety techniques.

Three Preparedness Scenarios

Anthropic plans for three possible futures:

  • Optimistic: AI development goes well. Safety research succeeds, and AI benefits everyone.
  • Intermediate: Some challenges arise but are manageable with careful governance and technical solutions.
  • Pessimistic: Significant risks materialize. Strong safety measures and governance structures are critical.

Key Research Areas

  • Mechanistic Interpretability: Understanding what's happening inside the model — why does it produce a specific output?
  • Scalable Oversight: Techniques for humans to effectively supervise AI systems as they become more capable.
  • Constitutional AI (CAI): Training AI to follow a set of principles (a "constitution") rather than relying solely on human feedback.

Responsible Use Principles

Five Responsible Use Guidelines
  • Always verify critical outputs with human review before acting on them
  • Don't use Claude for high-stakes decisions (medical diagnosis, legal advice, safety-critical systems) without expert oversight
  • Respect Anthropic's Acceptable Use Policy (AUP) — certain uses are prohibited
  • Be transparent about AI use with end users when appropriate
  • Don't share sensitive data unnecessarily in prompts — minimize data exposure

Governance Framework

Organizations deploying Claude should establish a governance framework that includes:

  1. Define acceptable use policies — What tasks can Claude be used for? What is off-limits?
  2. Establish review processes — Who reviews AI-generated content before it's published or acted upon?
  3. Train team members — Ensure everyone understands responsible AI use, prompt best practices, and output evaluation
  4. Monitor outputs — Track quality, accuracy, and compliance over time with regular audits

Content Filtering and Refusal Behavior

Claude has built-in safety classifiers that filter harmful content. Claude may decline requests that violate its safety policies or Anthropic's Acceptable Use Policy (AUP). Common reasons for refusal:

  • Requests for harmful, illegal, or unethical content
  • Attempts to generate malware, weapons instructions, or CSAM
  • Requests that could cause real-world harm to specific individuals
  • Some edge cases where Claude is overly cautious — in these cases, rephrasing the request with legitimate context usually resolves the issue

Enterprise Controls

Claude for Enterprise provides organizational safeguards:

  • SSO integration: Single sign-on with your identity provider

  • Usage policies: Enforce organizational rules about acceptable use

Optimization Strategies

Prompt Optimization

The most impactful optimization is improving your prompt. Small changes in wording, structure, or examples can dramatically improve output quality.

  • Iterate on wording — change one thing at a time and compare results
  • Add or remove constraints based on output quality
  • Include few-shot examples for complex or nuanced tasks
  • Use XML tags to separate instructions from data

Model Optimization

Use the cheapest model that meets your quality requirements. Don't default to the most expensive model for every task.

Hardest reasoning challenges

Cost Optimization

  • Prompt caching: Cache repeated prompt prefixes — cache hit costs 10% of normal input cost
  • Batch processing: 50% discount on all token costs for non-urgent bulk tasks
  • Shorter prompts: Remove unnecessary context and verbose instructions
  • Right-sized models: Don't use Fable for a task Haiku can handle

Latency Optimization

  • Use faster models (Haiku, Sonnet) for time-sensitive tasks
  • Shorter prompts mean faster responses
  • Streaming: show Claude's response token-by-token for perceived speed
  • Set appropriate max_tokens to prevent unnecessarily long responses

Quality Optimization

  • Enable thinking/chain-of-thought for complex reasoning tasks
  • Use the effort parameter to control how much thinking Claude does
  • Add more few-shot examples for nuanced tasks
  • Use prompt chaining to break complex tasks into manageable steps

Prompt Caching Basics

How Prompt Caching Works

When you send the same prompt prefix repeatedly (e.g., a long system prompt with policies and examples), caching stores it so subsequent requests only pay a fraction of the input cost.

  • 5-minute cache: Write cost = 1.25x input. Read cost = 10% of input. Pays off after just 1 read.
  • 1-hour cache: Write cost = 2x input. Read cost = 10% of input. Pays off after 2 reads.
  • Best for: system prompts, few-shot examples, and large context blocks that repeat across requests.

Batch Processing Basics

  • Submit multiple requests at once (up to thousands)
  • 50% discount on all token costs (input and output)
  • Results delivered asynchronously, typically within hours
  • Ideal for non-time-sensitive, large-volume tasks
  • Use cases: document classification, data extraction, content generation at scale

Debugging Techniques

  1. Examine Claude's reasoning: Enable thinking mode to see Claude's step-by-step reasoning process. This reveals where it goes wrong.
  2. Change one thing at a time: When iterating on a prompt, change only one element per attempt so you can identify what helps.
  3. Test with edge cases: Try unusual inputs, very long texts, ambiguous requests, and adversarial inputs.
  4. Compare models: Run the same prompt on different models — if Haiku fails but Sonnet succeeds, the task may need more reasoning capability.
  5. Simplify the prompt: If a complex prompt fails, strip it down to essentials and add elements back one by one.
