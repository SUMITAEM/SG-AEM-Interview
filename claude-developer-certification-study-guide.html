Endpoint

Everything goes through POST /v1/messages. Tools, structured outputs, thinking, and caching are all features of this single endpoint—not separate APIs.

Multi-Turn Conversation Pattern

Python from anthropic import Anthropic client = Anthropic() conversation = [] def chat(user_message: str) -> str: conversation.append({"role": "user", "content": user_message}) response = client.messages.create( model="claude-opus-5", max_tokens=4096, system="You are a helpful coding assistant.", messages=conversation ) assistant_text = response.content[0].text # Append the full content (not just text) to preserve structure conversation.append({"role": "assistant", "content": response.content}) return assistant_text

System Prompts

  • Set via the top-level system parameter, separate from messages.
  • System tokens count as input tokens and are billed at the input rate.
  • Keep stable system prompts first for optimal prompt caching.
  • Can be a plain string or an array of content blocks (with cache_control).
  • Mid-conversation system messages ("role": "system" in messages[]) are supported on Opus 4.8+, Fable 5+ to inject instructions without invalidating cache.

Content Block Types

Block TypeDirectionDescription
textBothPlain text content. Most common block type.
imageUser → APIBase64-encoded image or URL. Supports PNG, JPEG, GIF, WebP.
documentUser → APIPDF or text document. Base64 or Files API reference.
tool_useAPI → ClientClaude requests a tool call. Contains id, name, input.
tool_resultClient → APIResult of executing a tool. References tool_use_id.
thinkingAPI → ClientReasoning trace. Has thinking text and signature field.

Stop Reasons & Handling

Python response = client.messages.create(model="claude-opus-5", ...) match response.stop_reason: case "end_turn": # Normal completion - read response.content print(response.content[0].text) case "max_tokens": # Output was truncated - consider increasing max_tokens print("Warning: response truncated") case "stop_sequence": # Hit a custom stop sequence print("Stopped at custom delimiter") case "tool_use": # Claude wants to call a tool - enter agentic loop handle_tool_calls(response) case "refusal": # Safety classifier declined (Fable 5.1 / Opus 5+) category = response.stop_details.category print(f"Refused: {category}")
Response Usage Object

Every response includes response.usage with: input_tokens, output_tokens, cache_creation_input_tokens, and cache_read_input_tokens. Use these to track costs and cache performance.

Part 03Streaming & Real-Time Responses

Server-Sent Events (SSE) Protocol

When stream: true is set, the API returns an SSE stream. Each event has an event: type line followed by a data: JSON payload line. The stream delivers tokens incrementally as they are generated.

SSE Event Types

EventWhen FiredKey Data
message_startStream beginsMessage object with id, model, usage.input_tokens
content_block_startNew content block beginsBlock index and type (text, tool_use, thinking)
content_block_deltaIncremental contenttext_delta, input_json_delta, or thinking_delta
content_block_stopBlock is completeBlock index
message_deltaMessage-level updatestop_reason, usage.output_tokens
message_stopStream endsEmpty — signals completion
pingKeep-aliveEmpty — prevents timeout
errorStream errorError type and message

Python Streaming Example

Python from anthropic import Anthropic client = Anthropic() # Context manager approach - recommended with client.messages.stream( model="claude-opus-5", max_tokens=4096, messages=[{"role": "user", "content": "Explain async/await in Python."}] ) as stream: for text in stream.text_stream: print(text, end="", flush=True) # Get the final assembled message final_message = stream.get_final_message() print(f"\nTokens used: {final_message.usage.output_tokens}")

TypeScript Streaming Example

TypeScript import Anthropic from "@anthropic-ai/sdk"; const client = new Anthropic(); const stream = client.messages.stream({ model: "claude-opus-5", max_tokens: 4096, messages: [{ role: "user", content: "Explain async/await." }], }); stream.on("text", (text) => process.stdout.write(text)); const message = await stream.finalMessage(); console.log(`\nTokens: ${message.usage.output_tokens}`);

Streaming with Tool Use

When Claude makes a tool call during streaming, the events arrive as:

  1. content_block_start with type: "tool_use" containing the tool name and id
  2. Multiple content_block_delta events with input_json_delta (partial JSON for tool arguments)
  3. content_block_stop when the tool call arguments are complete
  4. message_delta with stop_reason: "tool_use"

Eager Input Streaming (Fine-Grained Tool Streaming)

Set eager_input_streaming: true on a tool definition to receive large tool inputs as they are generated, rather than waiting for the server to buffer the complete input. This is not a beta feature—no beta header needed. Use it only on streaming requests with client-side tools. The client must validate the parsed input against the schema, since the SDK's tolerant parser may silently return a truncated result.

Part 04Tool Use & Function Calling — Production Patterns

Tool Definition Schema

JSON { "name": "get_weather", "description": "Get current weather for a city. Returns temperature in Fahrenheit.", "input_schema": { "type": "object", "properties": { "city": { "type": "string", "description": "City name, e.g. 'San Francisco'" }, "units": { "type": "string", "enum": ["fahrenheit", "celsius"] } }, "required": ["city"], "additionalProperties": false }, "strict": true }

Complete Agentic Loop

Python import json from anthropic import Anthropic client = Anthropic() tools = [{ # tool definitions as above }] def execute_tool(name: str, inputs: dict) -> str: if name == "get_weather": return json.dumps({"temp": 72, "condition": "sunny"}) return json.dumps({"error": "Unknown tool"}) def run_agent(user_message: str): messages = [{"role": "user", "content": user_message}] while True: response = client.messages.create( model="claude-opus-5", max_tokens=4096, tools=tools, messages=messages ) # Append assistant response (full content, not just text) messages.append({"role": "assistant", "content": response.content}) if response.stop_reason == "end_turn": return response.content[-1].text # Process tool calls tool_results = [] for block in response.content: if block.type == "tool_use": result = execute_tool(block.name, block.input) tool_results.append({ "type": "tool_result", "tool_use_id": block.id, "content": result }) messages.append({"role": "user", "content": tool_results})

Use disable_parallel_tool_use: true inside tool_choice to limit Claude to one tool call per turn.

Strict Tool Use

Set strict: true as a top-level field on the tool definition (alongside name, description, input_schema), not on tool_choice. The schema must include additionalProperties: false and list all properties in required. This guarantees the tool call input validates exactly against your schema.

Tool Use Token Overhead

Each tool definition adds tokens to the system prompt. Approximate overhead per model:

  • A simple tool definition adds roughly 200–400 input tokens per tool.
  • For large tool sets (50+ tools), use tool search (tool_search_tool_regex_20251119 or tool_search_tool_bm25_20251119) with defer_loading: true on most tools to reduce per-request token overhead.

Part 05Structured Outputs & JSON Mode

output_config.format with json_schema

Constrains the response to match a JSON Schema. Use output_config: {format: {type: "json_schema", json_schema: {...}}} on messages.create().

Breaking Change: output_format is deprecated The old output_format parameter is deprecated. Use output_config: {format: {...}} instead. This is a required migration for all new code.

Python Example with Pydantic

Python from pydantic import BaseModel from anthropic import Anthropic client = Anthropic() class MovieReview(BaseModel): title: str rating: float summary: str pros: list[str] cons: list[str] # parse() auto-extracts the JSON schema from the Pydantic model response = client.messages.parse( model="claude-opus-5", max_tokens=1024, messages=[{"role": "user", "content": "Review the movie Inception"}], output_type=MovieReview ) # response.parsed is a validated MovieReview instance review = response.parsed print(f"{review.title}: {review.rating}/10")

TypeScript Example with Zod

TypeScript import Anthropic from "@anthropic-ai/sdk"; import { zodOutputFormat } from "@anthropic-ai/sdk/helpers/zod"; import { z } from "zod"; const client = new Anthropic(); const MovieReview = z.object({ title: z.string(), rating: z.number(), summary: z.string(), pros: z.array(z.string()), cons: z.array(z.string()), }); const response = await client.messages.create({ model: "claude-opus-5", max_tokens: 1024, messages: [{ role: "user", content: "Review the movie Inception" }], output_config: zodOutputFormat(MovieReview), });

Strict Tool Use as Alternative

For simpler structured data, you can define a tool with strict: true and instruct Claude to call it. This guarantees schema conformance on the tool input. However, output_config.format is preferred for general structured output because it constrains the response directly without requiring a fake tool call.

Schema Limitations

  • No recursive schemas (no $ref to self)
  • No minLength / maxLength on strings
  • No minimum / maximum on numbers
  • No pattern (regex) constraints
  • additionalProperties: false is required
  • All properties must be listed in required
  • Incompatible with citations (citations: {enabled: true} returns a 400)

Performance Notes

  • Grammar compilation — The first request with a new schema incurs a compilation cost. Subsequent requests with the same schema use a 24-hour cache.
  • Cache key — The full JSON schema is the cache key. Any change (even whitespace) creates a new compilation.

Part 06Prompt Caching — Implementation Guide

Two Caching Modes

Automatic Caching

Top-level cache_control: {"type": "ephemeral"} on the messages.create() call. The API automatically determines optimal breakpoints. Simplest option.

Explicit Breakpoints

Per-block cache_control on individual content blocks within system, tools, or messages. Max 4 breakpoints per request. Gives fine-grained control.

Python Code Examples

Python — Automatic response = client.messages.create( model="claude-opus-5", max_tokens=4096, cache_control={"type": "ephemeral"}, # top-level auto-caching system="You are a helpful assistant with expertise in Python.", messages=[{"role": "user", "content": "Explain decorators."}] )
Python — Explicit Breakpoints response = client.messages.create( model="claude-opus-5", max_tokens=4096, system=[ { "type": "text", "text": "<very long system prompt with guidelines...>", "cache_control": {"type": "ephemeral"} # breakpoint } ], messages=[{"role": "user", "content": "Summarize the guidelines."}] )

Minimum Token Requirements

The prefix must meet a minimum token count or it silently will not cache:

  • 512 tokens — Opus 5, Sonnet 5, Fable 5, Fable 5.1
  • 1024 tokens — Haiku 4.5
  • 2048–4096 tokens — Some older models

Tracking Cache Performance

Python usage = response.usage print(f"New input tokens: {usage.input_tokens}") print(f"Cache writes (new): {usage.cache_creation_input_tokens}") print(f"Cache reads (hits): {usage.cache_read_input_tokens}") # If cache_read_input_tokens is 0 across requests, check for invalidators

Cache Pre-Warming

Send a request with max_tokens: 0 to populate the cache without generating output. Useful for warming the cache before a burst of traffic.

Cache Invalidation Hierarchy

Prompt caching uses prefix matching. The render order is:

tools → system → messages Any byte change anywhere in the prefix invalidates everything after it. ↓ Keep stable content first ↓ Put volatile content (timestamps, IDs) after the last breakpoint ↓ Use deterministic JSON serialization for tool definitions
Common Silent Invalidators datetime.now() in system prompts, unsorted JSON keys in tool schemas, varying tool sets between requests, per-request UUIDs before the cache breakpoint. If cache_read_input_tokens is consistently 0, audit your prefix for any of these.

Multi-Turn Automatic Caching

In multi-turn conversations, the growing message history naturally extends the cached prefix. Each new turn adds content after the previous cache breakpoint, so prior turns hit cache while only the new content incurs write costs.

Key Rule: Cache Reads and Rate Limits

Cache read tokens do NOT count toward ITPM (Input Tokens Per Minute) rate limits. This means heavily cached workloads can process far more total tokens per minute than uncached ones.

Part 07Batch Processing

When to Use Batches

  • Large-volume processing — Thousands of requests that do not need real-time responses.
  • Evaluations — Running test suites against prompts.
  • Data processing — Classification, extraction, or summarization of large datasets.
  • Cost optimization — 50% cheaper than standard API calls.

JSONL Request Format

Each line is an independent request with a custom_id for correlation:

JSONL {"custom_id": "req-001", "params": {"model": "claude-sonnet-5", "max_tokens": 1024, "messages": [{"role": "user", "content": "Classify: positive or negative"}]}} {"custom_id": "req-002", "params": {"model": "claude-sonnet-5", "max_tokens": 1024, "messages": [{"role": "user", "content": "Summarize this review..."}]}}

Creating a Batch (Python)

Python from anthropic import Anthropic from anthropic.types.messages import MessageCreateParamsNonStreaming from anthropic.types.messages.batch_create_params import Request client = Anthropic() batch = client.messages.batches.create( requests=[ Request( custom_id="sentiment-001", params=MessageCreateParamsNonStreaming( model="claude-sonnet-5", max_tokens=256, messages=[{"role": "user", "content": "Classify as positive/negative: 'Great product!'"}] ) ), Request( custom_id="sentiment-002", params=MessageCreateParamsNonStreaming( model="claude-sonnet-5", max_tokens=256, messages=[{"role": "user", "content": "Classify as positive/negative: 'Terrible experience.'"}] ) ), ] ) print(f"Batch ID: {batch.id}")

Polling for Results

Python import time while True: batch = client.messages.batches.retrieve(batch.id) print(f"Status: {batch.processing_status}") if batch.processing_status == "ended": break time.sleep(60) # poll every minute

Retrieving Results

Python for result in client.messages.batches.results(batch.id): match result.result.type: case "succeeded": message = result.result.message print(f"{result.custom_id}: {message.content[0].text}") case "errored": print(f"{result.custom_id}: ERROR - {result.result.error}") case "canceled": print(f"{result.custom_id}: Canceled") case "expired": print(f"{result.custom_id}: Expired (24h limit)")
Batch Processing Key Facts
  • 50% cost savings compared to standard API requests
  • 100,000 requests maximum per batch
  • 24-hour processing window — results expire after 24 hours
  • Results arrive in any order — key by custom_id, never by position
  • Processing statuses: in_progress, ended, canceling, canceled, expired
  • Result types: succeeded, errored, canceled, expired

Part 08Thinking & Reasoning — Developer Guide

Adaptive Thinking (Current Standard)

On all current-generation models (Opus 4.6+, Sonnet 4.6+, Sonnet 5, Fable 5/5.1), use adaptive thinking. Claude dynamically decides when and how deeply to reason.

Python response = client.messages.create( model="claude-opus-5", max_tokens=16000, thinking={"type": "adaptive", "display": "summarized"}, messages=[{"role": "user", "content": "Prove that sqrt(2) is irrational."}] )

Extended Thinking (Legacy)

Only supported on Haiku 4.5 and older models. Uses a fixed token budget. This is deprecated for new code.

Python — Legacy (Haiku 4.5 only) response = client.messages.create( model="claude-haiku-4-5", max_tokens=16000, thinking={"type": "enabled", "budget_tokens": 8000}, messages=[{"role": "user", "content": "Solve this math problem..."}] ) # budget_tokens must be less than max_tokens, minimum 1024

Controls thinking depth. Set inside output_config, not top-level:

Thinking Blocks in Responses

When thinking is active, the response content array may include thinking blocks before text blocks:

Response Content Array [ { "type": "thinking", "thinking": "Let me analyze this step by step...", "signature": "dGhpbmtpbmdfc2lnbmF0dXJl..." }, { "type": "text", "text": "The answer is 42." } ]

Multi-Turn with Thinking (Signature Required)

When continuing a conversation, you must pass thinking blocks back unchanged, including their signature field. Never modify the thinking text or signature.

Python # Append the FULL content (including thinking blocks) back messages.append({"role": "assistant", "content": response.content}) messages.append({"role": "user", "content": "Can you elaborate?"}) # Thinking blocks with matching signatures will be accepted # Thinking blocks from a different model are silently dropped

Thinking with Tool Use

Thinking blocks can appear between tool calls. In an agentic loop, Claude may think before each tool call and again after processing results. The content array can look like: [thinking, tool_use, tool_use, ...] on one turn, then after tool results: [thinking, text] on the next.

Token Billing

  • Thinking tokens count as output tokens and are billed at the output rate.
  • They count toward max_tokens.
  • With display: "omitted" (default on newer models), thinking blocks are still generated and billed, but the thinking field is empty.
  • With display: "summarized", you get a readable summary (still not the raw chain of thought).
When to Use Thinking Thinking significantly improves performance on: mathematical proofs, complex coding tasks, multi-step analysis, agentic decision-making, and tasks requiring careful reasoning. For simple classification or extraction, lower effort or no thinking may be more cost-effective.

Cache-Aware ITPM

Cached tokens (reported as cache_read_input_tokens) do NOT count toward the ITPM rate limit. Only input_tokens and cache_creation_input_tokens count. This means a well-cached workload can effectively process far more total input per minute.

Token Bucket Algorithm

Rate limits use a token bucket model. The bucket fills at a constant rate (the limit) and drains with each request. Short bursts above the per-minute limit are allowed if the bucket has capacity, but sustained over-limit usage will trigger 429s.

Spend Limit Errors

Distinct from rate limits: error_code: "enforced_spend_limit_reached" means you have hit your monthly spending cap. This is a 400-level error, not a 429. Solution: increase the spend limit in the Console, not retry.

SDK Automatic Retries

Both the Python and TypeScript SDKs automatically retry on 429 (rate limit), 408 (timeout), 409 (conflict), and 5xx (server error) with exponential backoff. Default: 2 retries (configurable via max_retries). Wall-clock time can reach timeout x (max_retries + 1).

Part 10Testing, Evaluation & Quality Assurance

Defining SMART Success Criteria

Before building evaluations, define SMART criteria: Specific, Measurable, Achievable, Relevant, Time-bound. Example: "The model should correctly extract all invoice line items with at least 95% accuracy on the test set."

Five Evaluation Types

1. Exact Match

Python def eval_exact_match(expected: str, actual: str) -> float: return 1.0 if expected.strip().lower() == actual.strip().lower() else 0.0

2. Cosine Similarity (SBERT)

Python from sentence_transformers import SentenceTransformer from sklearn.metrics.pairwise import cosine_similarity model = SentenceTransformer("all-MiniLM-L6-v2") def eval_cosine_similarity(expected: str, actual: str) -> float: embeddings = model.encode([expected, actual]) score = cosine_similarity([embeddings[0]], [embeddings[1]])[0][0] return float(score)

3. ROUGE-L (Longest Common Subsequence)

Python from rouge_score import rouge_scorer scorer = rouge_scorer.RougeScorer(["rougeL"], use_stemmer=True) def eval_rouge_l(expected: str, actual: str) -> float: scores = scorer.score(expected, actual) return scores["rougeL"].fmeasure

4. LLM-Based Likert Scale

Best Practices

  • Use a different model for evaluation than the one being tested (prevents self-bias).
  • Include edge cases: empty inputs, very long inputs, adversarial prompts.
  • Automate your eval suite—run it after every prompt change.
  • Combine metrics: use both automated (exact match, ROUGE) and LLM-based judges.
  • Track scores over time to detect regressions.

Prompt Engineering Iteration Loop

1. Define success criteria (SMART, measurable) ↓ 2. Build evaluation set (20-50 test cases minimum) ↓ 3. Draft initial prompt ↓ 4. Run evaluations (automated + manual review) ↓ 5. Analyze failures (categorize error types) ↓ 6. Refine prompt (address specific failure modes) ↓ Loop back to step 4 until criteria are met

  • Store keys in environment variables (ANTHROPIC_API_KEY) or a secrets manager.

  • Set metadata.user_id for per-user abuse tracking.

Cost Optimization Strategies

Model Selection

Use the cheapest model that meets quality requirements. Haiku 4.5 for classification, Sonnet 5 for balanced tasks, Opus 5 for complex reasoning.

Prompt Caching

Cache stable prefixes (system prompts, tool definitions). Cache reads cost 0.1x. Biggest single lever for cost reduction.

Batch Processing

50% cost savings for non-latency-sensitive workloads. Use for evaluations, data processing, bulk operations.

Effort Tuning

Lower effort on simple tasks. A single model at lower effort often matches a cheaper model at high effort, while keeping cache benefits.

Monitoring

  • Usage page in the Console — total tokens, cost breakdown by model and workspace.
  • Rate limit charts — track utilization vs. limits across RPM, ITPM, OTPM.
  • Cache hit rates — monitor cache_read_input_tokens vs. cache_creation_input_tokens.
  • Response usage — every API response includes usage for per-request tracking.
