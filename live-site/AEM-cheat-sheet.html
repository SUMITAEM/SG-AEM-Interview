01 AEM Architecture & Basics

Technology Stack

AEM Application | +-- Apache Sling (RESTful resource resolution) | | | +-- JCR / Apache Jackrabbit Oak (content repository) | | | +-- OSGi / Apache Felix (modular runtime) | | | +-- Java VM
  • AEM = CMS built on Apache Sling + JCR (Jackrabbit Oak) + OSGi (Apache Felix)
  • Everything is stored in the JCR as nodes and properties (tree structure)
  • Sling maps URLs to JCR resources; OSGi manages service lifecycle

Instances

InstancePurposeDefault Port
AuthorContent creation, editing, workflow, preview4502
PublishContent delivery to end users4503
DispatcherApache/IIS module — caching, load balancing, security80/443

Replication

  • Forward replication: Author → Publish (activate/publish content)
  • Reverse replication: Publish → Author (e.g., user-generated content)
  • Replication agents configured under /etc/replication/agents.author

Run Modes

  • Set via sling.run.modes property in start script or JVM arg
  • Types: author, publish, dev, stage, prod
  • Control OSGi config activation, code behavior, and environment-specific settings

  • AEM = Sling + JCR (Oak) + OSGi (Felix) + Java
  • Author (4502) creates content; Publish (4503) delivers it; Dispatcher caches it
  • AEMaaCS: /apps is immutable, deploy only through Cloud Manager CI/CD
  • Run modes control which OSGi configs are active per environment
  • /apps overlays /libs — never modify /libs directly

02 OSGi Framework

Core Concepts

  • OSGi = modular Java framework; deploy/update/remove bundles at runtime without restart
  • A bundle = JAR with OSGi metadata in MANIFEST.MF
  • A component = class managed by OSGi with lifecycle and DI
  • A service = interface registered in the OSGi service registry

Bundle Lifecycle

INSTALLED --> RESOLVED --> STARTING --> ACTIVE | UNINSTALLED <-- STOPPING <-----------+
  • INSTALLED: JAR deployed but dependencies not resolved
  • RESOLVED: All imports satisfied; ready to start
  • ACTIVE: Bundle running, services registered
  • Common issue: stuck in INSTALLED → missing package import

Key Annotations (DS R6 — Preferred)

AnnotationPurpose
@ComponentDeclares a DS component (auto-registers as service if it implements an interface)
@ReferenceInject another OSGi service
@ActivateMethod called when component activates
@DeactivateMethod called when component deactivates
@ModifiedMethod called when configuration changes
@Designate(ocd=...)Links component to its OSGi configuration interface

OSGi Configurations

  • Config interface: @ObjectClassDefinition with @AttributeDefinition fields
  • Config file naming: com.example.MyService.cfg.json (or .config, .xml)
  • Run mode folders: config.author, config.publish, config.dev, config.stage, config.prod
  • Factory configs: append ~instance-id to PID, e.g., com.example.MyService~site1.cfg.json

Felix Console Endpoints

URLPurpose
/system/console/bundlesView all bundles & state
/system/console/componentsView DS components & state
/system/console/configMgrManage OSGi configurations
/system/console/servicesView registered services
/system/console/depfinderFind package dependencies

Service Ranking

  • When multiple implementations of the same service exist, highest ranking wins
  • Set via @Component(property = "service.ranking:Integer=1000")
  • Default ranking is 0; use to override OOTB implementations

Quick Recall

  • Bundle not ACTIVE? Check for missing imports (INSTALLED state = unresolved dependencies)
  • DS R6 annotations (@Component, @Reference) are preferred over SCR/R4
  • Config naming: PID + run-mode folder determines when config applies
  • Higher service.ranking = higher priority for multiple implementations

03 Apache Sling & Resource Resolution

What is Sling?

  • RESTful web framework that maps HTTP URLs to JCR resources
  • Request flow: URL → Resource → Script/Servlet
  • Content-centric: the URL determines the content node, the resource type determines the rendering

URL Decomposition

/content/mysite/en/page.selector1.selector2.html/suffix?key=val |__________________________| |_________________| |__| |_____| |______| resource path selectors ext suffix query
PartExamplePurpose
Resource path/content/mysite/en/pageJCR node to resolve
Selectorsselector1.selector2Select script variant (dot-separated)
ExtensionhtmlDetermines output format
Suffix/suffixAdditional path info for the script
Query paramskey=valStandard HTTP parameters

Sling Servlet Registration

By Path

  • sling.servlet.paths=/bin/myservlet
  • Ignores resource type
  • Cannot be access-controlled by JCR ACLs
  • Simpler; used for utility endpoints

By Resource Type

  • sling.servlet.resourceTypes=myapp/components/page
  • Tied to resource type + selectors + extension + method
  • Respects JCR ACLs
  • Preferred approach
  • SlingAllMethodsServlet — supports GET, POST, PUT, DELETE
  • SlingSafeMethodsServlet — GET and HEAD only

Sling Models

  • POJO classes annotated with @Model(adaptables = {Resource.class, SlingHttpServletRequest.class})
  • Injection strategy: defaultInjectionStrategy = OPTIONAL or REQUIRED
AnnotationInjects
@ValueMapValueJCR property value from the resource
@ChildResourceChild node as a resource
@SelfThe adaptable itself (request or resource)
@OSGiServiceAn OSGi service reference
@ResourcePathResource at a given JCR path
@ScriptVariableScript binding (currentPage, designer, etc.)
@PostConstructMethod runs after injection completes
@ExporterEnables JSON export via .model.json

ResourceResolver

  • Session-based — MUST be closed if opened manually (try-with-resources)
  • Never use getAdministrativeResourceResolver() — deprecated!
  • Use service users: map via Sling Service User Mapping OSGi config
  • Get resolver: resolverFactory.getServiceResourceResolver(authInfo)

Quick Recall

  • Sling = URL → Resource → Script/Servlet (content-centric)
  • Servlet registration by resource type is preferred over path-based
  • @ValueMapValue is the most common Sling Model injection annotation
  • ALWAYS close manually-opened ResourceResolvers (try-with-resources)
  • Use service users, never admin resource resolvers

04 JCR & Queries

JCR Fundamentals

  • JCR = Java Content Repository — hierarchical tree of nodes and properties
  • Every piece of content in AEM is a JCR node
  • Underlying implementation: Apache Jackrabbit Oak (with TarMK or MongoMK persistence)

Common Node Types

Node TypeUsage
nt:unstructuredFlexible, no schema constraints (most common)
cq:PageAEM page node
cq:PageContentPage content (jcr:content child of cq:Page)
dam:AssetDAM asset
nt:file / nt:resourceFile nodes with binary data
sling:FolderFolder with sling:resourceType support
sling:OrderedFolderOrdered child nodes

Mixins & Property Types

Common Mixins

  • mix:versionable — enable versioning
  • mix:lockable — node locking
  • mix:referenceable — UUID identifier

Property Types

  • String, Long, Double, Boolean
  • Date, Binary, Path, Name
  • Reference, WeakReference

Query Languages

1. SQL2 (Preferred)

SELECT * FROM [cq:Page] AS p
WHERE ISDESCENDANTNODE(p, '/content/mysite')
AND p.[jcr:content/jcr:title] = 'Home'

2. XPath (Legacy)

/jcr:root/content/mysite//element(*, cq:Page)
  [jcr:content/@jcr:title = 'Home']

3. QueryBuilder (AEM-Specific)

path=/content/mysite
type=cq:Page
property=jcr:content/jcr:title
property.value=Home
orderby=@jcr:content/jcr:created
orderby.sort=desc
p.limit=10
p.offset=0
  • REST API: /bin/querybuilder.json?path=/content&type=cq:Page
  • Predicates: fulltext, daterange, tagid, nodename, hasPermission
  • p.guessTotal=true for estimated total count

Oak Indexes

Index TypeUse CaseNotes
LuceneFull-text search, sortingMost versatile; stores data in Lucene docs
PropertyEquality lookupsFast for exact matches; no full-text
OrderedRange queries, sortingDeprecated in favor of Lucene
  • Indexes defined at /oak:index — node type oak:QueryIndexDefinition
  • Key properties: type, indexRules, includedPaths, propertyIndex=true
  • Always create custom indexes for production queries — never rely on traversal

Quick Recall

  • SQL2 is the preferred query language; XPath is legacy
  • QueryBuilder provides a predicate-based API and REST endpoint
  • ALWAYS create Oak indexes for queries — traversal = performance disaster
  • Check query performance at /system/console/queryperformance
  • nt:unstructured is the most common node type; cq:Page for pages

05 Components & HTL

Component Basics

  • Component = reusable building block with dialog (authoring) + template (rendering)
  • Structure: .content.xml (metadata), _cq_dialog (Touch UI), HTL file, clientlib
  • Component group: controls grouping in the sidekick/component panel (e.g., "SumitGroup")
  • Overlay vs Override: /apps overlays /libs via Sling Resource Merger

Core Components & Proxy Pattern

  • Core Components: adobe/cq/components — always extend, never modify directly
  • Proxy component: component in /apps with sling:resourceSuperType pointing to a Core Component
  • Allows customization while keeping upgrade path intact

  • Default context is html — auto-escaped for XSS protection

Touch UI Dialog Fields

  • Defined in _cq_dialog/.content.xml using Granite/Coral UI components
  • Common fields: textfield, textarea, pathfield, checkbox, select, datepicker, colorpicker, fileupload, multifield, richtext
  • Store values in jcr:content — read via Sling Models or ${properties.fieldName} in HTL

Quick Recall

  • Always use proxy components (sling:resourceSuperType) to extend Core Components
  • data-sly-use loads logic, data-sly-test does conditionals, data-sly-list iterates
  • HTL auto-escapes output (context='html') — prevents XSS by default
  • data-sly-resource includes child components; data-sly-include includes HTL files
  • Never use context='unsafe' unless absolutely necessary

06 Templates, Policies & Workflows

Editable Templates (Recommended)

  • Location: /conf/mysite/settings/wcm/templates
  • Template Types define the blueprint → Templates define page structure
  • Three layers:
    • Structure: locked components (header/footer) — cannot be edited by authors
    • Initial content: default content for new pages
    • Policies: component and style system configuration
  • Enable templates via allowedTemplates property on site root or cq:allowedTemplates on page

Static Templates (Legacy)

  • Location: /apps/mysite/templates
  • No runtime editing — changes require code deployment
  • Still used for older projects; migrate to editable templates where possible

Content Policies

  • Location: /conf/mysite/settings/wcm/policies
  • Configure per-template component behavior without code changes
  • Control: allowed components, style system classes, design properties
  • Applied via policy mapping in the template editor

Style System

  • Add CSS classes to components via Touch UI dialog without code changes
  • Configure in template policies → component → style tab
  • Groups of styles: e.g., "Layout" (full-width, centered), "Color" (dark, light)

Workflows

ConceptDetails
EngineGranite workflow engine (models at /var/workflow/models)
StepsProcess, Participant, OR Split, AND Split, Container
OOTB examplesRequest for Activation, DAM Update Asset, Project workflow
Custom stepsImplement WorkflowProcess.execute(WorkItem, WorkflowSession, MetaDataMap)
LaunchersAuto-trigger on node created/modified events (path, node type)
TransientDon't persist full history — better performance for DAM
  • Workflow launchers: configured via /libs/settings/workflow/launcher (overlay in /conf)
  • Launcher conditions: nodeType, glob (path pattern), eventType (ADDED, MODIFIED)

Quick Recall

  • Editable templates (/conf) = recommended; Static templates (/apps) = legacy
  • Template = structure (locked) + initial (defaults) + policies (config)
  • Style System adds CSS classes without code — configured in template policies
  • Custom workflow step: implement WorkflowProcess interface
  • Transient workflows skip history persistence — use for DAM processing

09 ClientLibs, Frontend & MSM

ClientLibs Basics

  • AEM mechanism to manage and serve CSS/JS files
  • Node type: cq:ClientLibraryFolder
  • Key properties:
    • categories: unique identifier string (e.g., mysite.page)
    • dependencies: other clientlibs loaded before this one
    • embed: merge other clientlibs into this one (single request, better perf)
  • css.txt lists CSS files; js.txt lists JS files (load order matters)

Including ClientLibs in HTL

<sly data-sly-use.clientlib="/libs/granite/sightly/templates/clientlib.html">
  <sly data-sly-call="${clientlib.all @ categories='mysite.page'}"/>
  <!-- .css = CSS only, .js = JS only, .all = both -->
</sly>

Webpack / Frontend Build

  • ui.frontend module: Webpack + TypeScript/ES6 + SCSS
  • Output compiled into /apps/mysite/clientlibs via aem-clientlib-generator
  • npm build → Maven copies output to ui.apps → deployed as package

Multi-Site Manager (MSM)

ConceptDetails
BlueprintSource site (master content)
Live CopyTarget site (inherits from blueprint)
Rollout ConfigRules for what gets synced and when
InheritanceLive copy inherits content; can be broken per component/page
Language Copyi18n — create translated versions of pages
  • Rollout triggers: on modification, on activation, manual
  • Conflict handling: rollout wins by default; can be customized
  • Detach live copy = permanently break inheritance

Launches & Versioning

  • Launches: create future versions of pages; promote on go-live date
  • Supports nested launches and promoting to other launches
  • Versioning: JCR versioning at /jcr:system/jcr:versionStorage
  • Create/restore/compare page versions via Timeline in Touch UI

Quick Recall

  • ClientLib categories = unique ID; use embed for performance (single request)
  • Include in HTL: data-sly-call="${clientlib.all @ categories='...'}"
  • MSM: Blueprint = source, Live Copy = target, Rollout Config = sync rules
  • Launches let you stage future content changes with a promotion date

10 Dispatcher & Caching

What is the Dispatcher?

  • Apache web server module (or IIS plugin) that sits in front of AEM Publish
  • Three primary functions: caching, load balancing, security filtering

Request Flow

Browser --> CDN --> Dispatcher (Apache) --> AEM Publish ^ | | Cache Layer | (static HTML files) +--- cached response

Configuration Sections (dispatcher.any)

SectionPurpose
/filterAllow/deny URL patterns (whitelist approach)
/cacheDefine what to cache: rules, docroot, statfileslevel, headers
/rulesCache rules within /cache section
/invalidateAuto-invalidation rules on activation
/rendersAEM Publish instances (render farm)
/virtualhostsDomain/hostname matching
/statisticsLoad balancing categories

Cache Invalidation

MethodHow It Works
Auto-invalidationOn publish/activate, dispatcher invalidates cached pages via stat file
Stat file.stat file touched on invalidation; cache files older than .stat are re-fetched
statfileslevelControls granularity: higher = more targeted invalidation
TTL-basedSet max-age headers; cache expires after time period
Flush agentsReplication agents on Author that trigger dispatcher flush

Security Filters

  • Block sensitive paths: /crx, /system/console, /bin/querybuilder.json
  • Allow only necessary URL patterns (whitelist approach)
  • Filter selectors to prevent DoS via selector bombing
  • Vanity URLs: short URLs mapped to content paths (configured on page properties)

CDN Integration

  • CDN (Fastly, CloudFront, Akamai) sits in front of Dispatcher
  • Caching hierarchy: Browser → CDN → Dispatcher → AEM
  • AEMaaCS includes Fastly CDN out of the box

Quick Recall

  • Dispatcher = caching + load balancing + security (Apache module)
  • statfileslevel controls invalidation granularity (higher = more targeted)
  • Always use whitelist /filter rules — block sensitive paths
  • Caching hierarchy: Browser → CDN → Dispatcher → AEM Publish
  • Stale cache? Check .stat file timestamp and invalidation rules

12 Performance & Best Practices

Caching Strategy

Browser Cache --> CDN --> Dispatcher Cache --> AEM Publish (max-age) (TTL/rules) (stat file) (renders)
  • Set appropriate Cache-Control headers
  • Use stale-while-revalidate for better UX during cache refresh
  • Cache static resources aggressively; invalidate content pages on publish

Query Performance

DoDon't
Create custom Oak indexesRely on traversal queries
Restrict queries with ISDESCENDANTNODEQuery from root (/)
Use p.limit to cap resultsFetch unbounded result sets
Use property indexes for equalityUse full-text search for exact matches
Monitor via /system/console/queryperformanceDeploy queries without testing

Code Best Practices

  • ResourceResolver: always close in try-with-resources; use service users
  • HTTP clients: set timeouts (connect + socket); close in try-with-resources
  • Sling Models: prefer OPTIONAL injection strategy; use @PostConstruct wisely
  • Logging: SLF4J only; never System.out; never log PII or API keys
  • JCR writes: batch and minimize; commit sessions promptly
  • Workflows: use transient workflows for DAM; avoid long-running synchronous steps

Frontend Performance

  • Lazy load images and below-the-fold components
  • Use async / defer attributes on script tags
  • Embed clientlibs to reduce HTTP requests
  • Minimize CSS/JS bundle size; tree-shake unused code
  • Use responsive images with srcset and Dynamic Media

Monitoring & Diagnostics

Log / ToolPurpose
request.logRequest timing and response codes
error.logApplication errors and exceptions
access.logHTTP access records
/system/console/queryperformanceSlow and popular queries
/system/healthAEM Health Check dashboard
/system/console/jmxJMX MBeans for monitoring
Developer Console (cloud)Logs, status, pods in AEMaaCS

Quick Recall

  • Cache hierarchy: Browser → CDN → Dispatcher → AEM
  • ALWAYS create Oak indexes for queries — traversal = unacceptable in production
  • Close ResourceResolvers in try-with-resources — leaks = memory/session exhaustion
  • Use transient workflows, lazy loading, embedded clientlibs for performance
  • Monitor: request.log, error.log, query performance console

13 Common Interview Code Snippets

1. Sling Servlet (GET)

@Component(service = Servlet.class, property = {
    "sling.servlet.paths=/bin/myservlet",
    "sling.servlet.methods=GET"
})
public class MyServlet extends SlingSafeMethodsServlet {

    @Override
    protected void doGet(SlingHttpServletRequest request,
                         SlingHttpServletResponse response)
                         throws IOException {
        response.setContentType("application/json");
        response.setCharacterEncoding("UTF-8");
        response.getWriter().write("{\"status\":\"ok\"}");
    }
}

2. Sling Servlet (POST with Service)

@Component(service = Servlet.class, property = {
    "sling.servlet.paths=/bin/myaction",
    "sling.servlet.methods=POST"
})
public class ActionServlet extends SlingAllMethodsServlet {

    @Reference
    private MyService myService;

    @Override
    protected void doPost(SlingHttpServletRequest request,
                          SlingHttpServletResponse response)
                          throws IOException {
        String param = request.getParameter("input");
        if (param == null || param.isEmpty()) {
            response.setStatus(400);
            response.getWriter().write("{\"error\":\"Missing input\"}");
            return;
        }
        String result = myService.process(param);
        response.setContentType("application/json");
        response.getWriter().write("{\"result\":\"" + result + "\"}");
    }
}

    @AttributeDefinition(name = "API Endpoint",
        description = "External API base URL")
    String apiEndpoint() default "https://api.example.com";

    @AttributeDefinition(name = "Timeout (ms)")
    int timeout() default 5000;

    @AttributeDefinition(name = "Enabled")
    boolean enabled() default true;
}

@Component(service = MyService.class, immediate = true)
@Designate(ocd = MyServiceConfig.class)
public class MyServiceImpl implements MyService {

    private String apiEndpoint;
    private int timeout;

    @Activate
    @Modified
    protected void activate(MyServiceConfig config) {
        this.apiEndpoint = config.apiEndpoint();
        this.timeout = config.timeout();
    }
}

Quick Recall

  • Servlet: @Component + service=Servlet.class + sling.servlet.paths property
